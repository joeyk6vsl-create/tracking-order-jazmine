# JAZMINE — ผังหน้าจอ

สถานะ: แบบวางแผนรอบแรกสำหรับเจ้าของตรวจ

เอกสารนี้อธิบายหน้าจอที่จะสร้างและผู้ใช้งานแต่ละหน้า ชื่อหน้าภาษาไทยใช้เพื่อคุยงาน หน้าระบบจริงใช้ภาษา Lao ตามข้อกำหนดเดิม รหัสหน้ามีไว้เชื่อมกับ `JAZMINE_USER_FLOWS.md`

## 1. หลักที่ใช้วางหน้า

- ใช้กฎล่าสุดจาก `JAZMINE_MASTER_RULES.md` และสิทธิ์จาก `JAZMINE_PERMISSION_MATRIX.md`

- ใช้ UI Design System เป็นแนวทางสี ตัวอักษร ปุ่ม และขนาดจอ
- เจ้าของคือ `ADMIN_PROMAX`; พนักงานคือ `STAFF` และแยกตามแผนก
- ทุกคนใช้ระบบเดียวกัน ปุ่มและข้อมูลเปลี่ยนตามสิทธิ์
- หน้าย่อย แบบฟอร์ม และกล่องยืนยันไม่จำเป็นต้องกลายเป็นเมนูใหม่ทั้งหมด

## 4. ลูกค้าและออเดอร์

ปรับหลังเจ้าของตรวจแบบร่าง: เมนูลูกค้าแสดงลูกค้าประจำเป็นหลัก หน้าสร้างออเดอร์เลือก “ลูกค้าขาจร” แล้วกรอกชื่อ/เบอร์เฉพาะงาน หรือ “ลูกค้าประจำ” แล้วเลือกข้อมูลเดิมได้ หลังยืนยันออเดอร์ขาจรจึงมีทางเลือกบันทึกเป็นลูกค้าประจำ โดยไม่ทำอัตโนมัติ การค้นหาออเดอร์ยังครอบคลุมทั้งสองแบบ

ตัวเลือกส่วนประกอบเสื้อใน S08 เปลี่ยนเป็นปุ่มรูปภาพพร้อมชื่อและสถานะเลือก ข้อมูลที่ไม่ใช่สินค้า เช่น มุมมองผู้ใช้ ยังใช้ตัวเลือกปกติได้

| รหัส | หน้า/รูปแบบ | ใครใช้ | ข้อมูลสำคัญ | ปุ่มหลักและปลายทาง |
|---|---|---|---|---|
| S04 | รายชื่อลูกค้า | เจ้าของ/ADMIN | ชื่อ เบอร์ กลุ่ม สถานะ ค้นหาและแบ่งหน้า | เปิดลูกค้า → S05; เพิ่มลูกค้า → S05 แบบสร้าง |
| S05 | รายละเอียดลูกค้า/แบบฟอร์ม | เจ้าของ/ADMIN | ข้อมูลติดต่อ กลุ่มลูกค้า ป้ายคอ เทปคอ ออเดอร์และยอดค้างของลูกค้ารายนั้น | บันทึก หรือสร้างออเดอร์ → S08 |
| S06 | รายการออเดอร์ | เจ้าของ/ADMIN | เลขออเดอร์ ลูกค้า วันนัด สถานะธุรกิจ สถานะเงิน ผลิตและส่ง แสดงแยกกัน | สร้างออเดอร์ → S08; เปิดรายการ → S07 |
| S07 | รายละเอียดออเดอร์ | เจ้าของ/ADMIN | แบบเสื้อ ไซซ์ ซื้อ/แถม ยอดล่าสุด รับแล้ว/ค้าง ประวัติแก้ งานผลิต เอกสารและการส่ง | ปุ่มตามงาน: แก้ → S08, รับเงิน → S17, เตรียมส่ง → S21, ดูงานผลิต → S12 |
| S08 | สร้าง/แก้ออเดอร์ | เจ้าของ/ADMIN | ลูกค้าและแบรนด์ ส่วนประกอบ ผ้ารายส่วน ไซซ์ จำนวน ของแถม ส่วนลด แบบตัวอย่าง | ตรวจสอบ → S09; บันทึกร่างพร้อมเหตุผลเมื่อเป็นการแก้ |
| S09 | ตรวจสอบก่อนยืนยัน/ก่อนบันทึกแก้ | เจ้าของ/ADMIN | สรุปข้อมูลทั้งหมด ราคาก่อนลด → เปอร์เซ็นต์ → จำนวนเงิน → ยอดสุดท้าย; ผลต่างจากฉบับเดิม | ยืนยัน → S07; กลับแก้ → S08 |
| S10 | เอกสารและประวัติเอกสารในออเดอร์ | เจ้าของ/ADMIN | ประเภท เลข ฉบับ วันออก สถานะเตรียม/ล้มเหลว/พร้อมเปิด และไฟล์ฉบับจริง | ออกใบเสนอราคาจากร่าง หรือเปิด/พิมพ์เอกสารที่มีสิทธิ์ |

ข้อกำหนดของหน้าชุดนี้:

- เบอร์โทรซ้ำแจ้งเตือนได้ แต่ไม่ใช้เป็นเหตุห้ามสร้างลูกค้า
- กลุ่มลูกค้ากับแบรนด์ผลิตเป็นคนละเรื่องกัน
- ถ้าเป็นแบรนด์ลูกค้า ต้องมีไฟล์ป้ายคอและเทปคอที่จำเป็นก่อนยืนยัน
- คอ ผ้า ไหล่ และปลายแขนต้องเลือกเองตาม Phase 5; ส่วนที่มีค่าเริ่มต้นใช้ค่าเริ่มต้นได้
- แยกจำนวนซื้อ จำนวนแถม และจำนวนที่ต้องผลิต/ส่ง
- ผ้าที่หมดก่อนยืนยันต้องแจ้งว่าเลือกยืนยันไม่ได้; ผ้าของงานที่ยืนยันแล้วหมดให้เตือนและห้ามเปลี่ยนแทนเงียบ ๆ
- ยืนยันครั้งแรกจึงได้เลขออเดอร์ถาวร; แก้ออเดอร์เดิมยังคงอ้างถึงออเดอร์เดิม
- ยืนยันแล้วมีใบแจ้งหนี้; ใบเสนอราคาเป็นทางเลือกก่อนยืนยัน ไม่ใช่เงื่อนไขบังคับ
- ใบเสร็จผูกกับรายการรับเงินจริง การรับเงินไม่สร้างใบแจ้งหนี้ฉบับใหม่
- การแก้ออเดอร์และจำนวนเงินต้องมีเหตุผลและประวัติ
- การเตรียมเอกสารที่ยังไม่เสร็จต้องไม่ทำให้ผู้ใช้เข้าใจว่ายืนยันออเดอร์ไม่สำเร็จ

## 5. งานกราฟิกและการผลิต

| รหัส | หน้า/รูปแบบ | ใครใช้ | ข้อมูลสำคัญ | ปุ่มหลักและปลายทาง |
|---|---|---|---|---|
| S11 | คิวการผลิต รวมมุมมองงานกราฟิก | เจ้าของ/ADMIN/GRAPHIC/ฝ่ายผลิตตามสิทธิ์ | เลขงาน ออเดอร์ ลูกค้า กำหนดส่ง ความเร่งด่วน ขั้นงาน และสถานะ; หนึ่งใบผลิตต่อหนึ่งแถว | เปิดงาน → S12; งานกราฟิก → S13 |
| S12 | รายละเอียดงานผลิต | เจ้าของ/ADMIN; พนักงานเฉพาะงานตน | แบบที่อนุมัติ แบรนด์ ไซซ์จัดสรร ส่วนผลิต ประวัติ ขั้นงานที่เริ่ม/จบได้ | เริ่มงาน/จบงานในแผนกตน; รายงานปัญหา → S15 |
| S13 | ไฟล์กราฟิกและการอนุมัติในงาน | GRAPHIC; เจ้าของ/ADMIN ดูประกอบงาน | รูปตัวอย่าง ไฟล์ผลิตแยกส่วน ฉบับปัจจุบัน/เก่า หมายเหตุ ผู้อนุมัติ | อัปโหลด/ส่งอนุมัติ/อนุมัติความพร้อมของไฟล์ → กลับ S12 |
| S14 | ตัวจัดทำใบผลิตและตัวอย่าง A4 | ผู้มีสิทธิ์จัดทำใบผลิตตามกฎเดิม | จำนวนแยกไซซ์ รูปแบบที่อนุมัติ ป้าย/เทปคอ ชิ้นส่วน ภาพ ผ้า หมายเหตุ | บันทึกร่าง/กำหนดพร้อมผลิต; ดู A4 → กลับ S12 |
| S15 | รายงานปัญหาในงาน | GRAPHIC/ฝ่ายผลิตเฉพาะงานตน; เจ้าของ/ADMIN | รายละเอียด ภาพ จำนวน/ไซซ์ที่เสียหายถ้ามี และเลือกทำต่อหรือหยุด | ส่งรายงาน → S12 พร้อมสถานะปัญหา |
| S16 | ตรวจและจัดการปัญหา | เจ้าของ/ADMIN | รายงาน งานที่ได้รับผลกระทบ จำนวนใช้ได้/เสีย/ต้องทำใหม่ และประวัติ | บันทึกวิธีแก้/สร้างงานทดแทน/อนุญาตทำต่อ → S12 |

หน้าจอ S12 บนคอมพิวเตอร์ใช้พื้นที่ข้อมูลหลัก 8 ส่วนและแผงควบคุม 4 ส่วนตาม Phase 5.19; S14 ใช้การจัดวางลักษณะเดียวกันตาม Phase 5.20 บนโทรศัพท์เรียงเป็นคอลัมน์เดียว

ข้อกำหนดของหน้าชุดนี้:

- GRAPHIC อนุมัติความพร้อมของไฟล์ผลิต ไม่ได้ยืนยันราคา รับเงิน หรือปิดปัญหาแทน ADMIN
- การจัดทำใบผลิต S14 เป็นอีกงานหนึ่งจากการอนุมัติไฟล์ S13 ผังนี้ไม่ขยายสิทธิ์ GRAPHIC ให้ยืนยันใบผลิตทั้งหมดโดยอัตโนมัติ
- รูปแบบที่ลูกค้าอนุมัติ กับไฟล์ที่พร้อมผลิตต้องมีป้ายแยกชัดเจน
- เอกสารฉบับเก่าเปิดอ่านได้และมีปุ่มไปฉบับปัจจุบัน
- รูปผลิตต้องเห็นครบ; ใบ A4 เพิ่มหน้าได้เมื่อข้อมูลมาก ไม่ตัดภาพหรือย่อตัวอักษรเกินข้อกำหนด
- งานแผนกถัดไปเริ่มได้เมื่อขั้นก่อนหน้าเริ่มหรือเสร็จแล้ว แต่จบได้เมื่อขั้นก่อนหน้าเสร็จเท่านั้น
- การรายงานทั่วไปทำงานต่อได้; เลือกหยุดแล้วต้องรอผู้มีสิทธิ์แก้ปัญหา
- ไม่ถามจำนวนรับ/จบทุกขั้นในงานปกติ; ใช้จำนวนจัดสรรในใบผลิตและสถานะขั้นงาน
- จำนวนพร้อมส่งมาจากของที่ผ่าน QC และเงื่อนไขปัญหาแล้ว

หน้ารายการเงินใช้ได้ทั้งการเข้าจากเมนูการรับเงินและจากออเดอร์ โดยเปิดข้อมูลชุดเดียวกัน คืนเงินไม่ต้องออกเอกสารให้ลูกค้า แต่ต้องมีบันทึกภายใน

เตรียมส่งล่วงหน้าได้โดยยังไม่เพิ่มจำนวนส่งแล้ว การส่งขณะค้างเงินมีคำเตือนให้ผู้มีสิทธิ์พิจารณา ออเดอร์ยกเลิก/ใช้ไม่ได้ หรือจำนวนเกินพร้อมส่ง ต้องแจ้งเหตุผลที่ยืนยันไม่ได้

## 7. ติดตามลูกค้า รายงาน และการจัดการ

| รหัส | หน้า/รูปแบบ | ใครใช้ | ข้อมูลสำคัญ | ปุ่มหลักและปลายทาง |
|---|---|---|---|---|
| S23 | ตรวจสิทธิ์ติดตามงาน | ลูกค้าที่มีลิงก์ติดตาม | ช่องตรวจเบอร์โทรตามข้อมูลออเดอร์ | ตรวจสอบ → S24 |
| S24 | ติดตามงานและส่งคำขอ | ลูกค้าที่ผ่านการตรวจ | สรุปออเดอร์ แบบที่อนุญาต ความคืบหน้ารวม พร้อมส่ง/ส่งแล้ว สถานะเงินแบบย่อ | ส่งคำขอทั่วไป/ส่งสินค้า/เร่งงาน; ดูสถานะคำขอ |
| S25 | คำขอลูกค้า | เจ้าของ/ADMIN | ประเภท รายละเอียด วันรับ สถานะ ผลพิจารณา และออเดอร์ | รับเรื่อง/บันทึกผล → S07 หรือ S21 เพื่อทำรายการที่จำเป็น |
| S26 | รายงานเจ้าของ | เจ้าของเท่านั้น | ช่วงเวลา ยอดขาย เงินรับ/คืน ยอดค้าง จำนวน และกำไรพร้อมสถานะต้นทุน | เลือกช่วงและเปิดรายละเอียดตามสิทธิ์ |
| S27 | พนักงานและบัญชี | เจ้าของเท่านั้น | ชื่อ สถานะ ระดับผู้ใช้ แผนก | สร้าง/เปลี่ยนแผนก/ปิดบัญชี/ตั้งรหัสชั่วคราว |
| S28 | สินค้า ผ้า ไซซ์ ราคา โปรโมชั่น และแบรนด์กลาง | เจ้าของ; ผู้ดูแลที่มีสิทธิ์เดิมเท่านั้น | รายการปัจจุบัน สถานะ พร้อมใช้/หมด ค่าเริ่มต้น และฉบับราคา | เปิดรายละเอียด แก้ร่าง หรือเปิดใช้ตามสิทธิ์ |
| S29 | อัตราแลกเปลี่ยนและต้นทุน | เจ้าของเท่านั้น | LAK/THB/USD อัตราที่กรอก หมวดต้นทุน หน่วย ราคา และรายการที่ยังขาด | บันทึกค่าใหม่โดยเก็บประวัติ |
| S30 | ข้อมูลเก่า | เจ้าของเท่านั้น | รายการเก็บถาวร เหตุผล ประวัติ และเงื่อนไขการลบ | เปิดประวัติ/เก็บถาวร/ลบเฉพาะรายการที่ผ่านเงื่อนไข |
| S31 | ค้นหา QR และการแจ้งเตือน | ผู้ใช้ภายในตามสิทธิ์ | ชนิดรายการ ผลค้นหา ข้อความแจ้ง และสิทธิ์ปลายทาง | เปิดรายการที่ตรงสิทธิ์; สแกนอย่างเดียวไม่เปลี่ยนข้อมูล |

S24 ห้ามแสดงเลขใบผลิตภายใน ชื่อผู้ปฏิบัติงาน ปัญหาภายใน ภาพแยกชิ้นผลิต หมายเหตุภายใน หรือเอกสารการเงินภายใน การติดตามหลายใบผลิตแสดงเป็นภาพรวมออเดอร์

S26 แสดงคำว่า “กำไรยังคำนวณไม่ครบ” เมื่อยังไม่มีต้นทุนเพียงพอ ยอดขายกับเงินที่รับจริงต้องมีชื่อกำกับแยกกัน

การเห็นยอดเงินรายออเดอร์เพื่อทำงานไม่ใช่สิทธิ์ดูรายงานยอดขายรวม สิทธิ์จัดการราคากลาง S28 ไม่ได้เกิดจากสิทธิ์ลดราคาบนออเดอร์

## 8. กติกาหน้าจอที่ใช้ร่วมกัน

| เหตุการณ์ | สิ่งที่ผู้ใช้ควรเห็น/ทำได้ |
|---|---|
| กำลังโหลด | ข้อความกำลังโหลด; ไม่แสดงตัวเลขที่ยังไม่รู้เป็นศูนย์ |
| ยังไม่มีรายการ | อธิบายและแสดงปุ่มเพิ่มเฉพาะคนที่มีสิทธิ์ |
| ค้นไม่พบ | แสดงคำค้น ตัวกรอง และปุ่มล้าง |
| กรอกไม่ครบ | ชี้ช่องและอธิบายว่าต้องเพิ่มอะไร โดยเก็บข้อมูลที่พิมพ์แล้ว |
| ไม่มีสิทธิ์ | บอกว่าเข้าไม่ได้และมีทางกลับหน้าที่ใช้ได้ |
| มีคนแก้ข้อมูลไปก่อน | แสดงว่าข้อมูลเปลี่ยน ให้ตรวจฉบับล่าสุดก่อนบันทึกใหม่ |
| การเชื่อมต่อขาดระหว่างบันทึก | บอกว่ายังตรวจผลไม่ได้ ให้ตรวจรายการล่าสุดก่อนลองซ้ำ; ข้อมูลกรอกยังอยู่ |
| บันทึกสำเร็จ | แสดงเลขอ้างอิง ผลล่าสุด และปุ่มไปขั้นถัดไป |
| ยกเลิก/คืนเงิน/ลบ | ให้ตรวจรายการ จำนวน และเหตุผลก่อนยืนยัน |

บนโทรศัพท์รายการยาวใช้บัตรข้อมูล ตัวกรองยุบได้ และยอดสรุปยังหาเจอ ส่วนรายละเอียดไม่บีบหลายคอลัมน์จนอ่านไม่ได้ ทุกหน้าต้องรองรับภาษา Lao ข้อความยาว ปุ่มที่กดง่าย และแป้นพิมพ์

## 9. สิ่งที่ผังนี้ยังไม่ถือว่าอนุมัติใหม่

- W1 ตัวอย่างสถานการณ์ยังรอตรวจรับตามแผนเดิม
- ราคาต้นทุนจริงและวิธีเฉลี่ยยังรอข้อมูล
- สิทธิ์ปลีกย่อยในการจัดทำใบผลิตและดูแลข้อมูลกลางต้องตามกฎ Phase เดิม หากยังไม่ชัดให้ทำเครื่องหมายรอตัดสินใจในแบบร่าง ห้ามเพิ่มสิทธิ์เอง
- แบบวางแผนนี้ยังไม่ใช่หน้าจอที่สร้างเสร็จหรือผ่านการทดลองกับพนักงาน
