# JAZMINE — แบบร่างหน้าจอรอบแรก

สถานะ: ทำแบบร่างสำหรับตรวจแล้ว ยังไม่เริ่มพัฒนาระบบจริง

## ขอบเขตและข้อมูลตัวอย่าง

แบบร่างรอบนี้แสดงในบทสนทนาให้ลองกดได้ ใช้ภาษาไทยเพื่อให้เจ้าของตรวจง่าย หน้าจอจริงใช้ภาษา Lao และ Noto Sans Lao ตามคู่มือโครงการ

ข้อมูลลูกค้า เบอร์โทร เลขออเดอร์ และราคาเป็นข้อมูลสมมติ การเข้าสู่ระบบ การสร้างลูกค้า การรับรองแบบ และการยืนยันเป็นการแสดงผลของแบบจำลอง ไม่มีรายการธุรกิจจริงเกิดขึ้น

ราคา 100,000 LAK ต่อเสื้อหนึ่งตัวใช้ตรวจตำแหน่งส่วนลดและยอดสรุป ไม่ใช่ตารางราคาที่ใช้ขายจริง ราคาผ้า/ส่วนประกอบในแบบร่างยังไม่ได้คำนวณจริงตาม Phase 3

## หน้าจอที่จัดวางแล้ว

| หน้า | ตำแหน่งหลัก | สิ่งที่ลองกดได้ |
|---|---|---|
| S01 เข้าสู่ระบบ | กล่องชื่อผู้ใช้และรหัสตัวอย่างตรงกลาง | เข้าหน้าหลักตัวอย่าง |
| S03 หน้าหลัก | เมนูด้านข้าง ข้อมูลบัญชีด้านบน งานประจำกลางหน้า | เปิดงาน เลือกลูกค้า และสลับมุมมองเจ้าของ/ADMIN/GRAPHIC/PRINTING |
| S04 รายชื่อลูกค้า | หัวหน้า ปุ่มเพิ่มลูกค้า ช่องค้นหา และรายการ | ค้นหาลูกค้าตัวอย่าง ดูกรณีไม่พบ และเปิดลูกค้า |
| S05 ลูกค้า | ข้อมูลติดต่อแยกจากแบรนด์การผลิต | เพิ่มลูกค้าสมมติ และเริ่มออเดอร์ |
| S06 ออเดอร์ | รายการพร้อมสถานะแยกจากข้อมูลเงินและผลิต | เปิดร่างหรือรายการยืนยันตัวอย่าง |
| S08 สร้าง/แก้ออเดอร์ | ข้อมูลเป็นกลุ่มทางซ้าย ยอดสรุปทางขวา | เลือกส่วนประกอบ ใส่ไซซ์/จำนวนซื้อ/แถม เปอร์เซ็นต์และส่วนลดเงิน |
| S09 ตรวจสอบ | ข้อมูลก่อนยืนยันทางซ้าย ยอดสุดท้ายและปุ่มยืนยันทางขวา | กลับแก้ หรือยืนยันตัวอย่าง |
| S07 ผลยืนยัน | แยกสถานะออเดอร์ ผลิต เงิน ส่ง และใบแจ้งหนี้ | กลับแก้ออเดอร์และใส่เหตุผล |

หน้าการผลิตและรายงานในแบบร่างแสดงเฉพาะพื้นที่ตัวอย่างเพื่อดูความต่างของเมนูตามบทบาท รายละเอียดหน้าชุดนั้นจะทำในรอบถัดไป

## การจัดวางบนคอมพิวเตอร์และมือถือ

การปรับหลังเจ้าของตรวจรอบแรก:

- เปลี่ยนคอ ผ้า ไหล่ ปลายแขน และแขนจากดรอปดาวน์เป็นปุ่มรูปภาพพร้อมชื่อ
- แบบจำลองเริ่มด้วยช่องรูปที่ยังไม่มีภาพจริง สามารถเลือก PNG/JPEG/WEBP จากเครื่องเพื่อลองหน้าตาได้ รูปอยู่เฉพาะในภาพจำลองรอบนั้น ยังไม่ใช่การอัปโหลดเข้าข้อมูลสินค้าจริง
- หน้าสร้างออเดอร์มีลูกค้าขาจรและลูกค้าประจำให้เลือก
- ลูกค้าขาจรต้องกรอกชื่อและเบอร์ก่อนยืนยัน แต่ไม่เข้ารายชื่อประจำเอง
- หน้าผลยืนยันมีปุ่มบันทึกเป็นลูกค้าประจำ รายชื่อประจำจึงไม่เพิ่มทุกครั้งที่สร้างออเดอร์

- คอมพิวเตอร์: เมนูด้านซ้ายและเนื้อหาด้านขวา หน้าออเดอร์มีแผงยอดสรุปแยกให้เห็นชัด
- จอเล็ก: เนื้อหาเรียงลงมา ข้อมูลออเดอร์อยู่ก่อนยอดสรุป ปุ่มไม่ทับข้อมูล
- เมนูมือถือรอบแรกแสดงเป็นแถวที่ขึ้นบรรทัดได้เพื่อให้ตรวจปลายทางง่าย ระบบจริงจะใช้เมนูเปิด/ปิดตาม Phase 5.3
- ช่องกรอกและปุ่มใช้ขนาดกดสะดวก มีเส้นแสดงเมื่อเลือกด้วยคีย์บอร์ด
- มีตัวเลือกความหนาแน่นของระยะห่างเพื่อเปรียบเทียบความอ่านง่าย

## สิ่งที่ตรวจแล้ว

- เส้นทางเข้าสู่ระบบ → ลูกค้า → สร้างออเดอร์ → ตรวจ → ยืนยันตัวอย่าง
- ค้นหาลูกค้าและกรณีไม่พบ
- ข้อมูลส่วนประกอบไม่ครบต้องแสดงข้อความก่อนยืนยัน
- เปลี่ยนส่วนลดแล้วผลตัวอย่างเปลี่ยน โดยคิดเปอร์เซ็นต์ก่อนส่วนลดเงิน
- แก้ออเดอร์ที่ยืนยันแล้วต้องมีเหตุผล และกลับไปแก้ยังเห็นเหตุผลที่กรอก
- มุมมองฝ่ายผลิตไม่มีปุ่มสร้างออเดอร์หรือรายงานกำไร
- มุมมองเจ้าของเห็นกำไรที่ยังมีข้อมูลต้นทุนไม่ครบ
- ตรวจการเรียงข้อมูลบนความกว้าง 320, 390 และ 1024 พิกเซล

ผลตรวจนี้เป็นการตรวจแบบจำลอง ยังไม่ใช่ผลทดสอบความปลอดภัย การรับเงิน หรือการคำนวณราคาของระบบจริง

## สิ่งที่เจ้าของตรวจในรอบนี้

1. ชื่อเมนูและตำแหน่งปุ่มเข้าใจง่ายหรือไม่
2. สร้างออเดอร์แล้วข้อมูลเรียงตามวิธีทำงานจริงหรือไม่
3. ราคาก่อนลด หลังลด และของแถมตรวจง่ายหรือไม่
4. ข้อมูลลูกค้ากับแบรนด์แยกชัดหรือไม่
5. มือถือใช้สะดวกหรืออยากย้ายข้อมูลใดขึ้นมาก่อน

## จุดเริ่มโค้ดระบบจริง

เจ้าของขอให้แจ้งก่อนเริ่มเขียนโค้ดระบบจริง ต้องปฏิบัติดังนี้:

1. บอกให้ชัดว่าขั้นออกแบบถึงจุดไหนแล้ว
2. แจ้งว่าจะเริ่มพัฒนาส่วนใดและทำให้ใช้งานอะไรได้
3. แจ้งก่อนสร้างโครงการแอป ระบบเข้าสู่ระบบ ฐานข้อมูล หรือระบบออเดอร์จริง

ลำดับพัฒนาที่วางไว้เริ่มจากพื้นฐานโครงการและผู้ใช้/สิทธิ์ จากนั้นลูกค้าและข้อมูลสินค้า ราคา แล้วจึงออเดอร์ คำขอแจ้งก่อนเริ่มไม่ได้ทำให้แบบร่างนี้กลายเป็นการอนุมัติให้เริ่มโค้ดระบบโดยอัตโนมัติ
