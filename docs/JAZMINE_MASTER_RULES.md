# JAZMINE — MASTER RULES

บันทึกการทำตามแผน W6/W10: เพิ่มสำเนา PDF พร้อมสถานะปัจจุบันทุกหน้า แยกจากต้นฉบับเดิมและตรวจใหม่ผ่านปุ่มพิมพ์ โดยใช้ความหมาย CANCELLED/VOIDED/Archive เดิม ไม่ถือว่าใบรับเงินจริงถูก VOIDED เพียงเพราะออเดอร์ยกเลิก เพิ่มตั้งค่าเก็บอัตโนมัติเฉพาะเจ้าของ เริ่มปิดไว้ เมื่อเปิดจะเริ่มช่วงรอ 15 วันจากที่ระบบตรวจพบว่าเงื่อนไขงาน/เงินครบ ไม่เดาข้อมูลเวลาเก่า กิจกรรมใหม่หรือการเปลี่ยนนโยบายเริ่มรอใหม่ ไม่ลบข้อมูลและไม่ย้อนการยกเลิก ดู `../JAZMINE/docs/DOCUMENT_STATUS_AND_AUTO_ARCHIVE_TH.md` ต้นฉบับ Phase 0–6 ไม่ถูกแก้

บันทึกการทำงานตามแผน W7/W10: เจ้าของ/ADMIN ตรวจและย้อนแผนใช้ต่องานผลิตทั้งชุดได้เมื่อมีหลักฐานสถานะก่อนปิดครบและยังไม่มีงานต่อเนื่องที่ขัดกัน คืนสถานะใบเก่าตามจริง ปิดใบที่สร้างจากแผน ไม่ลบฉบับ ไฟล์ หรือประวัติ ต้องใส่เหตุผล ตรวจผลทุกใบ และยืนยันว่าไม่มีงาน/ส่งเพิ่มจริง แผนเก่าที่ไม่มีหลักฐานครบ หรือมีงานเพิ่ม ปัญหา ส่งสินค้า หรือคำสั่งถัดไป ต้องตรวจจัดการด้วยคน ไม่ย้อนราคา เงิน หรือออเดอร์จากส่วนนี้ ใช้สิทธิ์ production.resolve เดิม ไม่เพิ่มสิทธิ์ GRAPHIC ดู `../JAZMINE/docs/REVERSE_PRODUCTION_REUSE_PLAN_TH.md` เป็นขอบเขตรุ่นที่ทำตามแผน ไม่แก้ต้นฉบับ Phase 0–6

คำยืนยันเจ้าของเพิ่มเติม 2 พฤศจิกายน 2026: **QR รับเงินใช้กีบ (LAK) และบาท (THB)** ตามที่ลูกค้าเลือก ตั้งค่าแยกสกุลโดยเจ้าของ ADMIN_PROMAX; ADMIN ใช้ QR ที่เปิดไว้กับใบแจ้งหนี้ได้ อัตราแลกเปลี่ยนยังให้เจ้าของกำหนด การสแกนไม่บันทึกเงินอัตโนมัติ ข้อมูลธนาคารจริงยังรอเจ้าของ ไม่มีบัญชีสมมติเปิดใช้ในข้อมูลร้าน ดู `../JAZMINE/docs/PAYMENT_QR_TH.md` ขอบเขต QR แบบใช้ซ้ำ/ไม่ล็อกยอดเป็นรูปแบบที่รุ่นนี้รองรับ ยังไม่รับรองทุกธนาคาร และไม่เปลี่ยนกฎเงินหรือสิทธิ์เดิม

**สถานะ:** กฎกลางฉบับเริ่มต้นที่เจ้าของยืนยันแล้ว  
**วันที่:** 31 ตุลาคม 2026  
**ภาษาหน้าจอเว็บแอป:** ภาษาลาวผสมภาษาอังกฤษ  
**ภาษาเอกสารอธิบาย:** ภาษาไทย

เอกสารนี้เป็นจุดเริ่มต้นสำหรับเจ้าของ พนักงาน นักพัฒนา และ AI ก่อนทำงานกับระบบ JAZMINE

บันทึกการทำตามแผน W6 เพิ่มเติม: ข้อมูลใบที่บันทึกแล้วกับสถานะเก็บ PDF แยกกัน ไฟล์เป็น ISSUED เมื่อจัดหน้าและเก็บสำเร็จแล้ว ระหว่างรอใช้ RENDER_PENDING/PREPARING และหากผิดพลาดใช้ FAILED ลองใหม่ด้วยเลขและฉบับเดิม ไม่ยืนยันออเดอร์หรือรับเงินใหม่เพื่อแก้ไฟล์ ไฟล์ที่เก็บสำเร็จดาวน์โหลดตามสิทธิ์เดิมและไม่ถูกเขียนทับเมื่อแก้ราคา/ยกเลิกเงิน/เปลี่ยนใบผลิต ดู `../JAZMINE/docs/STORED_PDFS_TH.md` การเก็บไฟล์อยู่ในฐานข้อมูลของรุ่นในเครื่องและรวมสำรองแล้ว ยังไม่เปิดบริการเก็บไฟล์ภายนอก

บันทึกการนำแผน W6 มาใช้: เจ้าของ/ADMIN ออกใบเสนอราคาจากร่างและราคาที่ระบบตรวจใหม่ได้ มีเลข QT และฉบับแยก ใบเก่าคงข้อมูลตอนออก ไม่สร้างยอดขาย/รับเงิน/งานผลิตจากการออกหรือสแกน QR บนใบนี้ใช้ให้ผู้มีสิทธิ์เข้าสู่ระบบเปิดฉบับตรงกระดาษ หลังยืนยันออเดอร์ให้ใช้ขั้นใบแจ้งหนี้ ประวัติใบเสนอราคาเดิมยังอยู่ การเก็บไฟล์ PDF อัตโนมัติเพิ่มแล้วตามบันทึกด้านบน ดู `../JAZMINE/docs/QUOTATIONS_TH.md` ใช้กฎเอกสารและสิทธิ์เดิม ไม่ใช่คำตัดสินใหม่ของเจ้าของ

# 1. วิธีใช้เอกสารชุดนี้

## 1.1 ลำดับความสำคัญ

ให้ยึดตามลำดับ:

1. คำตัดสินล่าสุดของเจ้าของที่บันทึกในเอกสารนี้
2. Phase 0
3. Phase 1
4. Phase 2
5. Phase 3
6. Phase 4
7. Phase 5 Final
8. Phase 6
9. Implementation Plan
10. คู่มือออกแบบหน้าจอ

Phase ช่วงหลังมีหน้าที่เพิ่มรายละเอียด ไม่ควรเปลี่ยนกฎจาก Phase ก่อนหน้าโดยเงียบ ๆ

## 1.2 เมื่อพบกฎขัดกัน

ห้ามคนหรือ AI เลือกกฎเอง ให้ทำดังนี้:

1. หยุดเฉพาะงานส่วนที่ขัดกัน
2. แสดงข้อความหรือความหมายของกฎทั้งสองฝั่ง
3. อธิบายผลกระทบด้วยภาษาง่าย
4. ขอคำตัดสินจากเจ้าของ
5. บันทึกคำตอบลง `JAZMINE_DECISION_LOG.md`
6. ปรับเอกสารที่เกี่ยวข้องให้ตรงกันก่อนทำงานต่อ

## 1.3 Phase 5 ที่ใช้จริง

ใช้เฉพาะ:

```text
JAZMINE_PHASE_5_FINAL.md
```

`JAZMINE_PHASE_5_LOCKED_ONLY.md` เป็นเอกสารเก่าและห้ามใช้แทน Phase 5 Final

## 1.4 ภาษาที่ใช้ในเว็บแอป

เจ้าของยืนยันให้ใช้ **ภาษาลาวเป็นหลัก ผสมภาษาอังกฤษตามความเหมาะสม** เป็นแนวทางเดียวกันทั้งเว็บแอป

- เมนู ปุ่ม ช่องกรอก สถานะ คำเตือน และข้อความแจ้งผล ใช้ภาษาลาวร่วมกับภาษาอังกฤษที่เหมาะกับงาน
- คำภาษาอังกฤษที่ใช้กันทั่วไป เช่น Order, Invoice, Production Sheet และ QR รวมถึงรหัสไซซ์และสกุลเงิน ใช้ภาษาอังกฤษได้ โดยใช้คำให้สม่ำเสมอทุกหน้า
- ใช้ฟอนต์ **Noto Sans Lao** และตรวจให้ข้อความลาวกับอังกฤษแสดงร่วมกันได้ถูกต้อง รวมถึงบนมือถือและเอกสารที่ออกจากระบบ
- คู่มือ คำอธิบายไฟล์ และรายงานงานให้เจ้าของยังใช้ภาษาไทยตามที่ตกลงไว้

การบันทึกคำตัดสินครั้งนี้เป็นการกำหนดแนวทางสำหรับงานต่อไป ข้อความภาษาไทยที่ยังมีในหน้าจอเดิมให้ทยอยปรับเป็นภาษาลาว/อังกฤษตามแผน ยังไม่ได้ถือว่าแปลครบแล้ว

# 2. ผู้ใช้งานและแผนก

## 2.1 ระดับผู้ใช้

ระบบมีสองระดับผู้ใช้:

```text
ADMIN_PROMAX = เจ้าของ
STAFF        = พนักงาน
```

`ADMIN_PROMAX` ไม่ใช่ชื่อแผนก แต่คือเจ้าของที่มีอำนาจสูงสุด

## 2.2 แผนก

พนักงาน `STAFF` ต้องอยู่ในหนึ่งแผนก:

```text
ADMIN
GRAPHIC
PRINTING
HEAT_TRANSFER
LASER
SIZE_SORTING
SEWING
QC_PACKING
```

พนักงานแผนก `ADMIN` ดูแลงานออเดอร์ เงิน และการส่งสินค้าตามสิทธิ์ที่กำหนด แต่ยังไม่ใช่เจ้าของ

พนักงานฝ่ายผลิตทำงานเฉพาะส่วนของแผนกตนเอง และไม่สามารถใช้สิทธิ์ของแผนกอื่นได้

พนักงานแผนก `GRAPHIC` รับผิดชอบจัดทำ แก้ไข และอนุมัติไฟล์กราฟิกที่ใช้ในการผลิต เมื่ออนุมัติแล้วต้องเก็บไฟล์ฉบับนั้นไว้เป็นประวัติ หากออเดอร์เปลี่ยนจนกระทบงานกราฟิก ต้องจัดทำและอนุมัติฉบับใหม่แทนการเขียนทับฉบับเดิม

รายละเอียดทั้งหมดอยู่ใน `JAZMINE_PERMISSION_MATRIX.md`

## 2.3 ลูกค้าประจำและลูกค้าขาจร

- ลูกค้าประจำ: เลือกจากรายชื่อที่บันทึกไว้ ใช้ข้อมูลเดิมเริ่มออเดอร์ใหม่ได้
- ลูกค้าขาจร: กรอกชื่อและเบอร์ในออเดอร์โดยตรง ไม่ต้องสร้างรายชื่อประจำก่อน
- ข้อมูลลูกค้าขาจรต้องเก็บกับออเดอร์จริงแต่ละครั้ง ห้ามใช้ชื่อลูกค้ารวมชื่อเดียวจนไม่รู้ว่างานเป็นของใคร
- ออเดอร์ขาจรยังค้นย้อนหลังจากชื่อ เบอร์ และเลขออเดอร์ได้
- เพิ่มเข้ารายชื่อลูกค้าประจำเฉพาะเมื่อเจ้าของหรือพนักงาน ADMIN เลือก “บันทึกเป็นลูกค้าประจำ” เอง
- การบันทึกเป็นลูกค้าประจำไม่เปลี่ยนข้อมูลประวัติในออเดอร์เก่า
- ทุกออเดอร์ยังต้องมีกลุ่มราคาที่ถูกต้องและข้อมูลแบรนด์ ป้ายคอ เทปคอครบตามกฎก่อนยืนยัน แม้ไม่สร้างรายชื่อลูกค้าประจำ
- หากพบชื่อหรือเบอร์ซ้ำให้เสนอรายการเดิมเพื่อตรวจสอบ ห้ามรวมคนหรือแบรนด์เข้าด้วยกันอัตโนมัติ

กฎนี้แทนที่เงื่อนไขในเอกสาร Phase เดิมที่สมมติว่าต้องสร้าง/เลือกลูกค้าในรายชื่อกลางก่อนทุกออเดอร์ รายละเอียดออเดอร์ขาจรใช้ข้อมูลลูกค้าที่เก็บกับออเดอร์นั้นเป็นหลัก

# 3. ราคา ส่วนลด และของแถม

## 3.1 รูปแบบส่วนลด

หนึ่งออเดอร์สามารถใช้พร้อมกันได้:

```text
ของแถม
+ ส่วนลดเปอร์เซ็นต์
+ ส่วนลดเป็นจำนวนเงิน
```

## 3.2 ลำดับการคำนวณ

```text
ราคาสินค้าและส่วนเพิ่มทั้งหมด
→ ลดเป็นเปอร์เซ็นต์
→ ลดเป็นจำนวนเงิน
→ ราคาสุดท้าย
```

ตัวอย่าง:

```text
ยอดก่อนลด       1,000,000 LAK
ส่วนลด 10%        100,000 LAK
ยอดหลังลด          900,000 LAK
ลดเพิ่ม              50,000 LAK
ราคาสุดท้าย         850,000 LAK
```

ของแถมเป็นสินค้าที่ต้องผลิตและส่งจริง แต่ไม่สร้างของแถมซ้ำจากตัวของแถมเอง

รองรับรายการที่เป็นของแถมล้วนโดยจำนวนซื้อ 0 และจำนวนแถมมากกว่า 0 วางก่อนหรือหลังรายการซื้อได้ ห้ามบันทึกรายการที่ซื้อและแถมเป็น 0 ทั้งคู่ คิดเงินเฉพาะซื้อ ส่วนจำนวนผลิต/ส่งใช้ซื้อบวกแถม หากเลือกอัตโนมัติต้องจัดแถมรวมเท่ากับสิทธิ์จากจำนวนซื้อเท่านั้น ถ้าแถมเองโดยไม่มีซื้อให้ใช้โหมดกำหนดเอง ยังตรวจสินค้า ผ้า ไซซ์ ราคา และไฟล์ตามเดิม ไม่สมมติราคาที่ไม่รู้เป็นศูนย์ ดู `../JAZMINE/docs/GIFT_ONLY_LINES_TH.md` นำกฎของแถมเดิมมาใช้ ไม่มีการแก้ Phase ต้นฉบับ

## 3.3 ผู้มีสิทธิ์ลดราคา

- เจ้าของ `ADMIN_PROMAX` ลดราคาได้
- พนักงาน `STAFF` แผนก `ADMIN` ลดราคาได้
- พนักงานฝ่ายอื่นลดราคาไม่ได้
- ไม่มีเพดานส่วนลดตายตัว
- ราคาสุดท้ายต้องไม่ต่ำกว่า 0

ระบบต้องบันทึกราคาก่อนลด ราคาหลังลด ผู้ที่ลด และวันเวลา

## 3.4 สกุลเงิน

ระบบรองรับ:

```text
LAK
THB
USD
```

ฐานการเงินของระบบคือ LAK การรับเงินสกุลอื่นต้องเก็บอัตราแลกเปลี่ยนที่ใช้กับรายการนั้น เพื่อให้ยอดเก่าไม่เปลี่ยนตามอัตราใหม่

เฉพาะเจ้าของ `ADMIN_PROMAX` เป็นผู้กรอก กำหนด และแก้อัตราแลกเปลี่ยนด้วยตนเอง พนักงานทุกแผนก รวมถึงแผนก `ADMIN` ไม่มีสิทธิ์เปลี่ยนอัตราแลกเปลี่ยน

เมื่อใช้อัตราแลกเปลี่ยนกับออเดอร์หรือรายการรับเงิน ระบบต้องเก็บอัตราที่ใช้ไว้กับรายการนั้น การแก้อัตราในอนาคตห้ามเปลี่ยนยอดของรายการเก่า

# 4. การสร้างและแก้ออเดอร์

## 4.1 ช่วงที่แก้ได้

ออเดอร์แก้ได้ทุกช่วง:

- ก่อนยืนยัน
- หลังยืนยัน
- ก่อนเริ่มผลิต
- หลังเริ่มผลิต
- ระหว่างผลิต

## 4.2 เหตุผลในการแก้

ทุกครั้งที่กดบันทึกการแก้ออเดอร์หลังจากสร้างครั้งแรก ต้องใส่เหตุผลก่อน ระบบไม่ควรถามเหตุผลทุกครั้งที่พิมพ์ แต่ถามเมื่อผู้ใช้กดบันทึกการเปลี่ยนแปลง

## 4.3 ประวัติ

ห้ามแทนที่ข้อมูลเก่าจนหายไป ระบบต้องเก็บ:

- ข้อมูลก่อนแก้
- ข้อมูลหลังแก้
- เหตุผล
- ผู้แก้
- วันและเวลา

ข้อมูลล่าสุดเป็นข้อมูลที่ใช้ทำงานปัจจุบัน ส่วนข้อมูลเก่าใช้ตรวจสอบประวัติ

## 4.4 ผลกระทบต่อเงิน

เมื่อราคาเปลี่ยน ให้ใช้ราคาล่าสุดเป็นยอดปัจจุบัน

```text
ราคาล่าสุด - เงินที่รับสุทธิแล้ว = ยอดคงเหลือปัจจุบัน
```

ถ้าราคาล่าสุดต่ำกว่าเงินที่รับแล้ว ให้แสดงว่าเงินเกินและรอการจัดการ ห้ามคืนเงินอัตโนมัติ

## 4.5 ผลกระทบต่อการผลิต

ถ้าแก้ข้อมูลหลังเริ่มผลิต:

- ห้ามลบประวัติงานที่ทำไปแล้ว
- แจ้งแผนกที่ได้รับผลกระทบ
- ทำคำสั่งผลิตฉบับใหม่เมื่อจำเป็น
- ถ้าของเดิมใช้ไม่ได้ ให้บันทึกเป็นของเสียหรืองานที่ได้รับผลกระทบ
- ถ้าต้องผลิตใหม่ ให้สร้างงานผลิตทดแทน

---

# 5. การรับเงินและคืนเงิน

## 5.1 เงินมัดจำ

ไม่มีจำนวนหรือเปอร์เซ็นต์มัดจำขั้นต่ำตายตัว เจ้าของหรือพนักงานแผนก `ADMIN` กำหนดจำนวนมัดจำของแต่ละออเดอร์ได้

## 5.2 ช่องทางรับเงิน

```text
CASH      = เงินสด
TRANSFER  = เงินโอน
```

รายการรับเงินต้องเก็บจำนวนเงิน สกุลเงิน อัตราแลกเปลี่ยน ช่องทาง วันเวลา ผู้รับเงิน และหมายเลขอ้างอิงถ้ามี

## 5.3 บันทึกเงินผิด

ห้ามแก้ทับรายการเดิมจนประวัติหาย ให้ใช้ขั้นตอน:

```text
ยกเลิกรายการที่ผิดพร้อมเหตุผล
→ สร้างรายการใหม่ที่ถูกต้อง
```

เจ้าของและพนักงานแผนก `ADMIN` ทำรายการแก้ไขนี้ได้

ทุกการเปลี่ยนแปลงที่กระทบจำนวนเงินต้องใส่เหตุผล

## 5.4 คืนเงิน

- คืนเต็มจำนวนได้
- คืนบางส่วนได้
- เฉพาะเจ้าของ `ADMIN_PROMAX` เท่านั้นที่คืนเงินได้
- ต้องใส่เหตุผลทุกครั้ง
- ไม่จำเป็นต้องออกเอกสารคืนเงินให้ลูกค้าใน V1
- ระบบยังต้องเก็บบันทึกภายในของการคืนเงิน

บันทึกภายในต้องมีจำนวน สกุลเงิน ช่องทาง วันเวลา ผู้คืน เหตุผล และรายการรับเงินที่เกี่ยวข้อง

---

# 6. ปัญหาในการผลิต

## 6.1 เมื่อพบปัญหา

พนักงานเลือกได้ว่า:

```text
REPORT_AND_CONTINUE = รายงานและทำงานต่อ
REPORT_AND_STOP     = รายงานและหยุดงานส่วนที่ได้รับผลกระทบ
```

การรายงานปัญหาไม่ทำให้งานหยุดอัตโนมัติทุกกรณี เฉพาะปัญหาที่ถูกเลือกให้หยุดเท่านั้นที่หยุดความคืบหน้าส่วนนั้น

## 6.2 ผู้จัดการปัญหา

- เจ้าของจัดการและปิดปัญหาได้ทุกประเภท
- พนักงานแผนก `ADMIN` จัดการและปิดปัญหาได้ทุกประเภท
- พนักงานฝ่ายผลิตรายงานปัญหาได้
- พนักงานฝ่ายผลิตทำงานต่อได้หากปัญหาไม่ได้ถูกกำหนดให้หยุด

## 6.3 สินค้าเสียหายหรือมีตำหนิ

ต้องบันทึกจำนวน ไซซ์ จุดที่เกิดปัญหา และสาเหตุ หากต้องผลิตชดเชย ให้สร้างงานผลิตทดแทนที่เชื่อมกับปัญหาเดิม

---

# 7. การส่งสินค้า

## 7.1 เงินค้างไม่ห้ามส่ง

ส่งสินค้าได้แม้ลูกค้ายังจ่ายไม่ครบ แต่ระบบต้องแสดงยอดค้างและคำเตือนชัดเจน

ผู้ที่อนุญาตและยืนยันการส่งได้:

- เจ้าของ `ADMIN_PROMAX`
- พนักงาน `STAFF` แผนก `ADMIN`

## 7.2 ส่งบางส่วน

ส่งสินค้าเพียงบางส่วนได้ ต้องระบุจำนวนและไซซ์ที่ส่งจริง ระบบต้องคำนวณจำนวนที่ยังเหลืออยู่

## 7.3 วิธีรับสินค้า

ต้องเลือกหนึ่งวิธี:

```text
CUSTOMER_PICKUP = ลูกค้ามารับเอง
SHOP_DELIVERY   = ร้านจัดส่ง
```

ถ้าร้านจัดส่ง ให้บันทึกผู้ให้บริการและหมายเลขติดตามเมื่อมีข้อมูล

## 7.4 เตรียมส่งกับส่งแล้ว

แยกเป็นสองสถานะ:

```text
PREPARED  = เตรียมรายการแล้ว แต่สินค้ายังอยู่ในร้าน
CONFIRMED = ผู้มีสิทธิ์ยืนยันส่งแล้ว รวมกรณีอนุญาตบันทึกล่วงหน้าก่อนสินค้าออกจากร้าน
```

แอดมินสามารถเตรียมรายการล่วงหน้าได้ แต่จำนวนที่ส่งแล้วจะเพิ่มเฉพาะเมื่อเป็น `CONFIRMED`

ตามคำสั่งโดยตรงของเจ้าของ เจ้าของและแผนก ADMIN ยืนยันส่งก่อนสินค้าออกจากร้านได้ โดยเลือกบันทึกว่าเป็นการยืนยันล่วงหน้า พร้อมเหตุผล และยังต้องมีจำนวนผ่าน QC ที่พร้อมส่งพอ การยืนยันล่วงหน้านับในยอดส่งแล้วตามรายการที่ยืนยัน ไม่ใช่หลักฐานว่าสินค้าออกจากร้านจริงแล้ว

ถ้าบันทึกผิด ให้ยกเลิกรายการพร้อมเหตุผล แล้วจึงสร้างหรือยืนยันรายการที่ถูกต้อง ห้ามลบประวัติเดิม ข้อนี้แทนข้อความเดิมที่บังคับ CONFIRMED เฉพาะหลังสินค้าออกจริง โดยไม่แก้ต้นฉบับ Phase 0–6

---

## 7.5 QR ติดตามบนใบแจ้งหนี้

เจ้าของ/ADMIN เลือกใส่ QR ติดตามในใบแจ้งหนี้ได้ ใช้ระบบลิงก์สุ่มและยืนยันเบอร์เดิม เก็บเฉพาะรหัสตรวจสอบ ไม่ดึงลิงก์ลับเดิมกลับมาเอง วางลิงก์ที่คัดลอกไว้เพื่อพิมพ์ซ้ำได้โดยไม่สร้างทดแทน การสร้างทดแทนหรือปิดลิงก์ทำให้ QR เก่าใช้งานไม่ได้ตามกฎเดิม ต้องตรวจว่าเป็นออเดอร์เดียวกัน ไม่หมดอายุและยังไม่ปิด ก่อนแนบและผ่านปุ่มพิมพ์ QR เปิดสถานะล่าสุด แต่ราคาและจำนวนในเอกสารคงฉบับที่เลือก การสแกนไม่บันทึกธุรกรรม QR ชำระเงินแยกต่างหาก และต้องใช้ที่อยู่เว็บที่ลูกค้าเข้าถึงก่อนส่งใบจริง ดู `../JAZMINE/docs/INVOICE_TRACKING_QR_TH.md` นำ Phase 5 Final ข้อ 5.12 และ Phase 6 ข้อ 6C.19 มาใช้ ไม่แก้ต้นฉบับ

# 8. ข้อมูลเก่า

## 8.1 ซ่อนหรือเก็บถาวร

เฉพาะเจ้าของสามารถซ่อนหรือเก็บข้อมูลเก่าออกจากหน้าทำงานประจำได้ ข้อมูลยังค้นหาและเรียกดูประวัติได้

รุ่นทดลองเพิ่ม Archive ที่เจ้าของกดเองตามเงื่อนไขแล้ว งานปกติต้องส่งครบ เงินครบ ไม่มีงานค้าง และพ้น 15 วันหลังส่งครบโดยไม่เร็วกว่าวันยืนยันฉบับล่าสุด งานยกเลิกต้องเคลียร์ข้อตกลงการเงินและงานค้างก่อน เก็บแล้วไม่ลบประวัติหรือยอดขายย้อนหลังของออเดอร์ปกติ เมื่อมีรายการเงิน การแก้งาน หรือคำถามลูกค้าใหม่ ระบบแสดงกลับในรายการทำงานพร้อมประวัติ เพิ่มการเก็บอัตโนมัติตามนโยบายที่เจ้าของเลือกเปิดแล้ว เริ่มปิดไว้และนับช่วงรอ 15 วันจากการตรวจพบเงื่อนไขครบ หากมีร่างออเดอร์ปกติที่แก้แต่ยังไม่ยืนยัน ต้องตรวจให้ชัดก่อนเก็บ

การยกเลิกออเดอร์แยกจากการยกเลิกรายการเงิน: เจ้าของ/ADMIN ตรวจผลกระทบและยกเลิกพร้อมเหตุผลได้ ประวัติเงิน งานผลิตจริง และการส่งที่ยืนยันแล้วยังคงอยู่ รายการที่เพียงเตรียมส่งถูกปิดพร้อมเหตุผล ห้ามผลิตหรือส่งเพิ่มในออเดอร์ยกเลิก เจ้าของต้องระบุยอดสุดท้ายทั้งหมดที่ตกลงให้ร้านได้รับ ระบบคำนวณต้องคืน/รับเพิ่มจากยอดรับสุทธิ แต่ต้องบันทึกรายการเงินจริงแยก ไม่เดาว่าคืนทั้งหมดหรือเก็บทั้งหมด ออเดอร์ยกเลิกไม่รวมยอดขายหรือความต้องการผลิตปัจจุบัน แต่เงินจริงยังอยู่ในรายงาน ยอดที่ยังไม่ตกลงต้องแสดงว่ารอตัดสิน ไม่ถือว่าเงินค้างศูนย์ ดูคู่มือ `../JAZMINE/docs/CANCEL_AND_ARCHIVE_ORDERS_TH.md` แนวทางนี้นำกฎ Cancel/financial resolution/Archive ของ Phase 0, 3 และ 6 มาใช้ร่วมกับสิทธิ์เจ้าของเดิม ไม่แก้เอกสารต้นฉบับ

## 8.2 ลบถาวร

เฉพาะเจ้าของทำได้ และต้องมี:

- ระยะเวลาเก็บขั้นต่ำตามที่ระบบกำหนด
- หน้าสรุปสิ่งที่จะถูกลบ
- เหตุผล
- การยืนยันชัดเจน
- บันทึกว่าใครทำและทำเมื่อไร
- การสำรองข้อมูลตามนโยบาย

เลขออเดอร์และเลขเอกสารที่เคยใช้แล้วห้ามนำกลับมาใช้ใหม่

# 9. ยอดขาย ต้นทุน และกำไร

## 9.1 สูตรกำไร

```text
รายได้จากการขาย
- ต้นทุนผ้าที่ใช้ผลิตเสื้อ
- ค่าแรงงาน
- ค่าน้ำหมึกและวัสดุที่ใช้พิมพ์
- ต้นทุนการผลิตอื่น ๆ
= กำไรโดยประมาณ
```

## 9.2 หมวดต้นทุนเริ่มต้น

ระบบต้องรองรับอย่างน้อย:

```text
FABRIC_COST       = ต้นทุนผ้า
LABOR_COST        = ค่าแรงงาน
PRINTING_INK_COST = ค่าน้ำหมึกและวัสดุพิมพ์
OTHER_COST        = ต้นทุนการผลิตอื่น
```

ต้นทุนอื่นต้องมีชื่อ รายละเอียด จำนวนเงิน และเหตุผล ห้ามรวมเป็นตัวเลขที่ไม่รู้ที่มา

## 9.3 ราคาต้นทุนยังไม่พร้อม

ขณะนี้ยังไม่มีราคาหรืออัตราต่อหน่วยของต้นทุนแต่ละประเภท จึงให้เตรียมพื้นที่สำหรับกรอกภายหลัง

ระหว่างที่ข้อมูลต้นทุนยังไม่ครบ:

- ระบบแสดงยอดขายได้
- ระบบแสดงต้นทุนที่บันทึกไว้ได้
- ระบบต้องแสดงว่า `กำไรยังคำนวณไม่ครบ`
- ห้ามถือว่าต้นทุนที่ไม่มีข้อมูลเท่ากับ 0
- ห้ามแสดงกำไรเป็นตัวเลขที่ดูเหมือนสมบูรณ์

เฉพาะเจ้าของ `ADMIN_PROMAX` ดูรายงานกำไรได้ เพื่อความปลอดภัย เริ่มต้นให้เฉพาะเจ้าของเป็นผู้กำหนดหรือแก้ราคาต้นทุนด้วย หากภายหลังต้องการมอบหมายให้พนักงาน ให้เพิ่มสิทธิ์อย่างชัดเจน

# 10. กฎการออกแบบหน้าจอ

ส่วนประกอบเสื้อ เช่น คอ ผ้า ไหล่ ปลายแขน และแขน ใช้ปุ่มที่มีรูปภาพและชื่อให้เลือกแทนดรอปดาวน์ เมื่อเลือกแล้วต้องมีทั้งข้อความ “เลือกแล้ว” และลักษณะที่เห็นชัด หากยังไม่มีรูปให้แสดงช่องว่างพร้อมชื่อจริง ห้ามใช้ภาพที่ทำให้เข้าใจผิดว่าเป็นสินค้าอีกชนิด

ใช้ `reference/JAZMINE_UI_DESIGN_SYSTEM_V1.md` เป็นคู่มือหน้าตาหลักของ JAZMINE และใช้ `reference/apple-layout-guide.md` เป็นแนวทางประกอบเรื่อง:

- ภาษาลาวผสมภาษาอังกฤษ และการตัดบรรทัด
- โทรศัพท์ แท็บเล็ต และคอมพิวเตอร์
- ปุ่มและช่องกรอกที่กดง่าย
- สถานะกำลังโหลด ไม่มีข้อมูล ผิดพลาด และสำเร็จ
- การใช้งานด้วยคีย์บอร์ด
- ความอ่านง่ายและสีที่ชัดเจน

กฎหน้าตาห้ามเปลี่ยนกฎทางธุรกิจในเอกสารนี้

UI Design System มีข้อความสถานะเดิมว่าใช้สำหรับ Phase 5B ที่ยังเหลืองาน ข้อความนี้ถือเป็นประวัติของไฟล์ออกแบบ ไม่ใช่สถานะโครงการปัจจุบัน สถานะปัจจุบันให้ยึด `JAZMINE_PHASE_5_FINAL.md` ซึ่งระบุว่า Phase 5 เสร็จและล็อกแล้ว

6. สร้างเฉพาะส่วนนั้น
7. ทดสอบสิทธิ์ ประวัติ และการกดซ้ำ
8. ให้เจ้าของตรวจรับก่อนเริ่มส่วนถัดไป

ลำดับสร้างระบบ:

```text
ผู้ใช้และการเข้าสู่ระบบ
→ ลูกค้า สินค้า ไซซ์ ผ้า และรูปภาพ
→ ราคาและส่วนลด
→ ออเดอร์และเอกสาร
→ การผลิต
→ การรับเงินและคืนเงิน
→ การส่งสินค้า
→ หน้าติดตามสำหรับลูกค้า
→ รายงานและการค้นหา
```

# 12. ข้อมูลที่ยังรอกรอก

1. ราคาหรืออัตราต่อหน่วยของผ้าที่ใช้ผลิตเสื้อ
2. วิธีคิดค่าแรง เช่น ต่อชิ้น ต่อขั้นตอน หรือต่อช่วงเวลา
3. ราคาน้ำหมึกและวิธีเฉลี่ยค่าน้ำหมึกต่อออเดอร์
4. รายการต้นทุนการผลิตอื่นและราคาของแต่ละรายการ
