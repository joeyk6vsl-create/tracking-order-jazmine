# ตรวจเส้นทางใช้งานตั้งแต่ต้นจนจบ

เพิ่ม `catalog-order-entry.mjs` เพื่อทดสอบจากฐานใหม่ที่ยังไม่ตั้งผ้า/ไซซ์: เพิ่มสินค้าพร้อมภาพใหญ่กว่า 128 KB → ส่งคำขอเดิมหลังผลบันทึกหายโดยไม่สร้างซ้ำ → รายการไม่มีภาพแสดงชื่อ → เจ้าของตั้งผ้า/ไซซ์และกลุ่มราคาเอง → กดเลือกผ้าและไซซ์ → บันทึกร่างขาจร → ตรวจไฟล์และออกเลขออเดอร์จริง → อัปโหลด QR แล้วตรวจอัตโนมัติและแจ้งขั้นตอนก่อนบันทึก ตรวจ 320/390px พอร์ต 5193/3117 และฐานในหน่วยความจำแยกจากร้าน ภาพใน test-results เป็นข้อมูลทดสอบเท่านั้น

เพิ่ม archive-document-status.mjs: เจ้าของเปิดตั้งค่าเก็บอัตโนมัติ/ลองคำขอเดิมหลังขาดการเชื่อมต่อ → ตรวจช่วงรอ/เก็บ/เปิดกลับ → ปฏิเสธ ADMIN แก้ค่าตั้ง → ออเดอร์ยกเลิกหลังเปิดใบแล้วกดพิมพ์ตรวจใหม่ → สำเนาสถานะจริงทั้งสี่ชนิดและต้นฉบับไม่เปลี่ยน → อ่าน QR จาก PNG ทุกหน้าที่มี QR → พิมพ์ใบรับเงิน/ใบผลิต/ใบเสนอราคา และเครือข่ายขาดแล้วหยุดพิมพ์ ตรวจ 320/390px ใช้พอร์ต 5192/3116 และข้อมูลจำลอง PDF current-status-*.pdf กับรูปใน test-results เป็นไฟล์ตรวจระบบ ไม่ใช่เอกสารลูกค้าจริง เพิ่มท้าย pnpm test:e2e แล้ว

เพิ่ม `production-reversals.mjs`: ADMIN เปิดตรวจทุกใบ → ย้อนแผน READY ที่ยังมีเพียงสถานะงานเดิม → เชื่อมต่อขาดหลังบันทึก/ลองเดิมไม่ซ้ำ → เลือกแผนใหม่ → GRAPHIC อนุมัติ → บันทึกงานเพิ่มแล้วบล็อกการย้อน → สิทธิ์ GRAPHIC/บุคคลทั่วไปและมือถือ 320/390px ใช้ฐานในหน่วยความจำแยก พอร์ต 5191/3115 ไม่มีการเปลี่ยนข้อมูลร้าน ภาพ `test-results/production-reversal-desktop.png`, `production-reversal-mobile.png` และ `production-reversal-blocked.png` เพิ่มใน `pnpm test:e2e` แล้ว

เพิ่ม `payment-qr.mjs`: เจ้าของตั้ง LAK/THB → ขาดการเชื่อมต่อหลังบันทึก/ลองเดิมไม่ซ้ำ → ADMIN แนบสองสกุลร่วม QR ติดตาม → ปิด QR ก่อนพิมพ์แล้วบล็อก → เปลี่ยนใบระหว่างรอแล้วไม่พิมพ์ใบเก่า → ดาวน์โหลดต้นฉบับคงเดิม → อ่าน QR จริงจาก PDF 1/2/5 หน้า → สิทธิ์และมือถือ 320/390px ใช้ข้อมูลสมมติ TEST ONLY DO NOT PAY และฐานแยก พอร์ต 5190/3114 ต้องมี `pdftoppm` หรือ `PDFTOPPM_EXECUTABLE` เพิ่มท้าย `pnpm test:e2e` แล้ว

เพิ่ม `stored-documents.mjs`: ใช้ worker จริงสร้าง/เก็บ PDF ทั้งใบเสนอราคา ใบแจ้งหนี้ ใบรับเงิน และ PS รวม PDF แนบ → แสดงสถานะ/ดาวน์โหลดจากเว็บ → เทียบไฟล์ตรงทุกข้อมูล → VOIDED และเปลี่ยนฉบับแล้วไฟล์เก่าคงเดิม → ปฏิเสธคนไม่เข้าสู่ระบบ/GRAPHIC สำหรับเอกสารการค้า → ลองคำขอเดิมหลังการเชื่อมต่อขาดไม่ซ้ำ → ตรวจ 320/390px และอ่าน QR จากภาพ PDF จริง มาตรฐานหนึ่งหน้า PS รวมแนบสามหน้า และใบเสนอราคา 30 รายการห้าหน้า ใช้ฐานในหน่วยความจำ พอร์ต 5189/3113 และไฟล์ `test-results/stored-*` แยกจากร้าน

เพิ่ม `quotations.mjs`: ADMIN เปิดร่าง → ตรวจและออกใบ → จำลองการเชื่อมต่อขาดหลังบันทึกแล้วลองคำขอเดิม → ไม่ออกฉบับซ้ำ → แก้ร่างแล้วออกฉบับใหม่โดยราคาเก่าคงเดิม → QR เปิดฉบับตรงกระดาษ → ผู้ไม่เข้าสู่ระบบ/GRAPHIC เปิดข้อมูลไม่ได้ → พิมพ์ PDF A4 ตัวอย่างหนึ่งหน้าและ 30 รายการห้าหน้า → อ่าน QR จากภาพ PDF จริง → ตรวจ 320/390px และยืนยันว่าไม่มีออเดอร์ เงิน หรือใบผลิตเพิ่ม ใช้พอร์ต 5188/3112 ฐานในหน่วยความจำ และไฟล์จำลอง `test-results/quotation*` ใช้ `pdftoppm` และ `jsqr` เช่นชุดใบแจ้งหนี้

เพิ่ม `invoice-tracking.mjs`: ADMIN สร้างลิงก์จากใบแจ้งหนี้ → ใส่ QR → ปุ่มพิมพ์ตรวจซ้ำ → PDF A4 ตัวอย่างหนึ่งหน้า → อ่าน QR จากภาพ PDF จริงตรง URL → ลูกค้ายืนยันเบอร์ → เปิดใบใหม่แล้ววางลิงก์เดิมไม่หมุนลิงก์ → รายการยาว 30 รายการ/หกหน้า QR อยู่ครบหนึ่งตำแหน่ง → เลือกฉบับเก่าโดยราคาเดิมไม่เปลี่ยน → ปิดลิงก์ก่อนพิมพ์แล้วไม่เปิดหน้าพิมพ์ ตรวจ 320/390px พอร์ต 5187/3111 และฐานในหน่วยความจำแยกจากร้าน PDF/ภาพสมมติ `test-results/invoice-tracking*` ใช้ `pdftoppm` หรือกำหนด `PDFTOPPM_EXECUTABLE` เพื่อแปลง PDF เป็นภาพ และ `jsqr` เฉพาะชุดทดสอบเพื่ออ่าน QR เพิ่มใน `pnpm test:e2e` ต่อจากชุดเดิม

เพิ่ม `gift-only.mjs`: ADMIN เปลี่ยนรายการแรกเป็นแถมล้วน/กลับเป็นคิดเงิน → ห้ามปุ่มย้ายแถมล้างรายการอื่น → ไม่รับรายการว่าง → ซื้อครบแถมร่วมส่วนลด → บันทึกแล้วขาดการเชื่อมต่อ/ลองเดิมไม่เพิ่มฉบับ → ยืนยันและตรวจใบแจ้งหนี้ยอดแถม 0 → ตรวจผลผลิต/QC/ส่งรวมของแถมผ่านบริการจริงและดูสถานะส่งกลับบนเว็บ ตรวจคอมและมือถือ 320/390px ใช้ฐานในหน่วยความจำ พอร์ต 5186/3110 แยกจากร้าน ภาพ `gift-only-line-desktop.png`, `gift-only-line-mobile.png`, `gift-only-invoice.png` เพิ่มใน `pnpm test:e2e` ต่อจากชุดเดิม

เพิ่ม `order-lifecycle.mjs`: ADMIN ตรวจผลกระทบ → ยกเลิก → การเชื่อมต่อขาดหลังบันทึก → Retry ครั้งเดียว → เจ้าของกรอกยอดสุดท้าย → ใช้ปุ่มคืนเงินจริงบางส่วน → Archive → เปิด Include archived orders → ตรวจประวัติ → Restore visibility โดยยัง Cancelled → ฝ่ายผลิตถูกหยุดคำสั่งและไม่มีสิทธิ์จัดการวงจรออเดอร์ ตรวจคอมและมือถือ 320/390px ใช้ฐานในหน่วยความจำ พอร์ต 5185/3109 แยกจากร้าน ภาพสมมติ `order-cancellation-desktop.png`, `cancellation-agreement-mobile.png`, `order-archive-history.png` เพิ่มใน `pnpm test:e2e` ต่อจากชุดเดิม

เพิ่ม `issue-corrections.mjs`: ADMIN เปิดปัญหาที่ปิดแล้ว → เทียบจำนวนก่อน/หลัง → ลดร่างทดแทนพร้อมกัน → ตรวจชิ้นงานและใส่เหตุผล → จำลองขาดการเชื่อมต่อหลังบันทึก → Retry เก็บการแก้ครั้งเดียว → ตรวจยอดพร้อมส่งและประวัติแรกไม่หาย → พนักงานผลิตเข้าเส้นทางอ่าน/บันทึกการแก้ไม่ได้ ใช้ฐานในหน่วยความจำและพอร์ต 5184/3108 แยกจากข้อมูลร้าน ตรวจมือถือ 320/390px ภาพอยู่ใน `test-results/issue-correction-*.png` เพิ่มใน `pnpm test:e2e` หลังชุดเดิม

เพิ่ม `production-revisions.mjs`: ADMIN เปิดทบทวนออเดอร์ฉบับใหม่ → เลือกจำนวนใช้ต่อ → ขาดการเชื่อมต่อหลังบันทึก → Retry ไม่สร้างซ้ำ → ร่างรอ GRAPHIC → กราฟิกตรวจและทำใบใหม่ให้พร้อม → ฝ่ายผลิตเห็นที่มาและสถานะที่ทำแล้ว → สิทธิ์พนักงาน → A4/PDF ที่ระบุ Continued from สองหน้าสำหรับตัวอย่างมาตรฐาน ตรวจมือถือ 320/390px ใช้ช่อง 5183/3107 กับฐานในหน่วยความจำ ภาพและ PDF สมมติอยู่ใน `test-results/production-revision-*` ใบ PDF ใช้ภาพเล็กสำหรับตรวจระบบ ไม่ใช่งานลูกค้าจริง `pnpm test:e2e` เรียกชุดนี้ต่อจากเส้นทางเดิม W9 และสำรอง

W10 เพิ่ม `backups.mjs`: เจ้าของดาวน์โหลดไฟล์จริงด้วยรหัสภาษาลาว → ระบบปฏิเสธรหัสผิด → กู้คืนแล้วขาดการเชื่อมต่อ → Retry ไม่เพิ่มสำเนา → เปิดฐานที่กู้ขึ้นมาจริง → เข้าสู่ระบบใหม่ → ตรวจเงินและไฟล์แนบ → การเข้าโปรแกรมเดิมยังทำงาน → พนักงานเข้าไม่ได้ ตรวจมือถือ 320/390px ใช้พอร์ต 5178/3105 และสำเนา 5179/3106 แยกจากผู้ใช้ ภาพ `backup-recovery-desktop.png`, `backup-recovery-mobile.png`, `recovered-workspace.png` และไฟล์สำรองข้อมูลสมมติอยู่ใน `test-results` คำสั่ง `pnpm test:e2e` เรียกเส้นทางเดิม W9 และ W10 ตามลำดับ

งาน W9 อยู่ใน `tracking-reports-search.mjs`: เจ้าของสร้างลิงก์/QR → ลูกค้าตรวจเบอร์ → ภาพตัวอย่างที่อนุมัติและงานรวม → คำขอเร่งงาน → Retry หลังขาดการเชื่อมต่อไม่เพิ่มเรื่อง → แอดมินรับเรื่อง/ตอบ → ลูกค้าเห็นเฉพาะคำตอบสาธารณะ → รายงานเจ้าของ → ค้นหาและเปิดปลายทาง → พนักงานเห็นเฉพาะงานผลิต → ปิดลิงก์แล้วสิทธิ์สิ้นสุด ตรวจมือถือ 320/390px ด้วย ใช้ฐานข้อมูลในหน่วยความจำและพอร์ตทดสอบ 5175/3102

ภาพ W9 อยู่ใน `test-results/customer-tracking-desktop.png`, `customer-tracking-mobile.png`, `owner-reports-desktop.png` และ `owner-reports-mobile.png` เป็นข้อมูลทดสอบ ไม่ใช่งานจริง `pnpm test:e2e` เรียกทั้งเส้นทางเดิมและ W9 ตามลำดับ

เพิ่มเส้นทาง W8: รับมัดจำ → จำลองขาดการเชื่อมต่อ → Retry ไม่รับซ้ำ → แก้ยอดผิดโดยเก็บใบเดิม → คืนบางส่วนโดยเจ้าของ → ใบรับเงิน A4 หน้าเดียว → เตรียมส่งบางส่วน → ยืนยันล่วงหน้าขณะค้างเงิน → Retry ไม่ส่งซ้ำ → เพิ่มเลขติดตามพร้อมประวัติ ตรวจพนักงานผลิตเข้าเมนู/ข้อมูลการเงินไม่ได้ และหน้าจอ 320/390px ไม่ล้น

ภาพ `payments-delivery-mobile.png`, `payments-delivery-desktop.png` และใบรับเงินทดสอบ `payment-receipt.pdf` อยู่ใน `test-results` เป็นข้อมูลสมมติสำหรับตรวจระบบ ไม่ใช่เอกสารเงินของร้าน

`receipt-print.mjs` ใช้ฐานข้อมูลทดสอบแยก ตรวจใบรับเงินพื้นขาว A4 หน้าเดียวและเวลาลาวแม้เบราว์เซอร์ใช้เขตเวลานิวยอร์ก เรียกหลัง `pnpm build:server` ด้วย `node tests/e2e/receipt-print.mjs` ใช้พอร์ตทดสอบ 5174/3101 เช่นเดียวกับชุดหลัก จึงเรียกแยกกัน

เส้นทางที่ตรวจแล้ว: เข้าสู่ระบบ → ลูกค้าขาจร/ประจำ → สินค้าและผ้า → ราคา/ส่วนลด/แถม → ร่างหลายไซซ์ → ตรวจกราฟิก → ยืนยันออเดอร์ → ใบแจ้งหนี้ → แบ่งใบผลิต → แนบชิ้นงาน → ออกฉบับ → พิมพ์ A4/PDF → คิวงานแต่ละแผนก → Start/Complete

เพิ่มเส้นทางปัญหา: Report + Stop → ยืนยันของเสีย/Replacement → การลองคำขอเดิมเมื่อการเชื่อมต่อขาดโดยไม่มีร่างซ้ำ → เปิดร่างทดแทน เตรียมไฟล์ → Start/Complete ทั้งหกแผนก → QC → ยอดพร้อมส่งสุทธิเพิ่มถูกต้องโดยไม่เพิ่มออเดอร์ ภาพ `production-issues-mobile.png` และ `production-exceptions-readiness.png` อยู่ใน `test-results`

คิวงานตรวจการทำงานซ้อนกันตามลำดับ Start/Complete การส่งคำขอเดิมหลังการเชื่อมต่อขาด หมายเหตุที่เว้นว่างได้ และพนักงานพิมพ์ที่เปิดได้เฉพาะงานของแผนกตนเอง ภาพอยู่ใน `test-results/production-work-owner.png` และ `test-results/staff-mobile.png`

มี `identity-flow.mjs` ตรวจผ่านเบราว์เซอร์ถึงฐานข้อมูล โดยเปิดฐานในหน่วยความจำแยกจากข้อมูลผู้ใช้ ตรวจทั้งจอคอมและมือถือ รวมการส่งคำขอซ้ำเมื่อขาดการเชื่อมต่อ สิทธิ์พนักงาน ใบผลิตฉบับเก่า PDF แนบหลายหน้า และการแบ่งหน้าเมื่อชื่อ/หมายเหตุยาว ภาพและเอกสารผลตรวจอยู่ใน `test-results` ตัวอย่าง PDF ที่ใช้เปิดดูอยู่ใน `output/pdf/JAZMINE_PRODUCTION_SAMPLE.pdf` เป็นข้อมูลทดสอบ ไม่ใช่งานจริง
