# เก็บ PDF ที่ออกแล้ว และดาวน์โหลดไฟล์เดิม

เพิ่ม **Download current-status copy** แล้ว เพื่อได้สำเนาที่แสดงสถานะ ณ เวลาดาวน์โหลดทุกหน้า ต้นฉบับเดิมยังอยู่และไม่ถูกเขียนทับ การพิมพ์ผ่านปุ่มในหน้าเว็บตรวจสถานะใหม่ด้วย ดู [คู่มือสถานะเอกสารและเก็บอัตโนมัติ](DOCUMENT_STATUS_AND_AUTO_ARCHIVE_TH.md)

ระบบสร้างและเก็บไฟล์ให้เองหลังบันทึกข้อมูลใบเรียบร้อยแล้ว ครอบคลุม **ใบเสนอราคา ใบแจ้งหนี้ ใบรับเงิน และใบผลิต** เมื่อพร้อม ปุ่ม Download stored PDF จะดาวน์โหลดไฟล์ที่เก็บไว้ ไม่คำนวณราคาใหม่หรือสร้างหน้าตาเอกสารขึ้นใหม่ตอนดาวน์โหลด

## เริ่มใช้งาน

1. หยุดโปรแกรมที่เปิดอยู่ด้วย Ctrl+C แล้วเปิด `START_JAZMINE.cmd` ใหม่และรีเฟรชเว็บ ข้อมูลเดิมยังอยู่
2. เปิดเอกสารตามตารางด้านล่าง
3. มองหาส่วน **Stored original PDF** รอข้อความ **Original PDF stored**
4. กด **Download stored PDF** เพื่อเก็บไฟล์ลงเครื่อง

| เอกสาร | เปิดตรงไหน |
|---|---|
| ใบเสนอราคา | เมนู Quotations → เลือกเลขและฉบับ |
| ใบแจ้งหนี้ | ออเดอร์ที่ยืนยันแล้ว → เลือกออเดอร์และฉบับ |
| ใบรับเงิน | Payments & delivery → เลือกออเดอร์ → เปิดใบรับเงินรายการนั้น |
| ใบผลิต | เตรียมใบผลิต → เลือกใบและฉบับ → เปิดหน้า A4 |

ใบเสนอราคา ใบแจ้งหนี้ และใบรับเงิน ใช้บัญชีเจ้าของหรือ ADMIN ใบผลิตใช้เจ้าของ ADMIN หรือ GRAPHIC ตามสิทธิ์เดิม ลูกค้าและพนักงานแผนกผลิตทั่วไปไม่ได้สิทธิ์ดาวน์โหลดเอกสารภายในจากลิงก์นี้

## ข้อความที่อาจพบ

| ข้อความบนหน้าจอ | ความหมายและสิ่งที่ควรทำ |
|---|---|
| Waiting for preparation | รอระบบจัดเอกสารเดิมเข้ารายการทำไฟล์ |
| PDF queued | ข้อมูลใบถูกบันทึกแล้ว กำลังรอสร้างไฟล์ |
| Preparing PDF | ระบบกำลังจัดหน้า รูป และเอกสารแนบ |
| Original PDF stored | เก็บไฟล์สำเร็จ ดาวน์โหลดได้ มีเลขฉบับ จำนวนหน้า และเวลาที่เก็บ |
| PDF preparation failed | ยังเก็บไฟล์ไม่สำเร็จ ระบบลองให้อัตโนมัติได้ถึง 5 ครั้ง หากยังติดขัด ให้แก้สาเหตุก่อน ใส่ Retry reason และกด Retry PDF preparation |
| Retry same PDF request | การเชื่อมต่อขาดจนยังไม่ทราบผล ใช้ปุ่มนี้ถามผลคำขอเดิม |
| Current record changed | ออเดอร์หรือใบปัจจุบันเปลี่ยนแล้ว เช่น มีฉบับใหม่หรือยกเลิกรับเงิน ไฟล์ที่ดาวน์โหลดยังคงต้นฉบับเดิมไว้ดูประวัติ |

ใช้ **Refresh PDF status** เพื่อตรวจสถานะอีกครั้ง หน้าเว็บจะตรวจให้ระหว่างรอด้วย ไม่ต้องออกเลขใบใหม่เพียงเพราะ PDF ยังไม่พร้อม การลองใหม่ใช้เลขและฉบับเดิม ถ้าปิดโปรแกรมระหว่างทำไฟล์ ระบบจะกลับมาทำรายการที่ค้างต่อเมื่อเปิดใหม่

การบันทึกออเดอร์หรือรับเงินสำเร็จ กับการเก็บ PDF สำเร็จ เป็นคนละสถานะ ถ้า PDF ติดขัด อย่าบันทึกรับเงินซ้ำหรือยืนยันออเดอร์ใหม่เพื่อแก้ปัญหาไฟล์ ให้ใช้ส่วนสร้างไฟล์เดิมนี้

## เมื่อแก้ออเดอร์หรือยกเลิกรับเงิน

แก้ออเดอร์และยืนยันเป็นฉบับใหม่ → มีไฟล์ใบแจ้งหนี้ของฉบับใหม่ ไฟล์เก่ายังอยู่ตามเลขและฉบับเดิม

แก้หรือยกเลิกรับเงิน → เก็บใบรับเงินต้นฉบับไว้ และแจ้งสถานะปัจจุบันแยกบนหน้าจอ ไฟล์เก่าที่ดาวน์โหลดไม่ได้ถูกเขียนคำว่า VOIDED ทับย้อนหลัง ต้องดูสถานะปัจจุบันประกอบก่อนนำไปใช้

แก้ใบผลิตและออกฉบับใหม่ → เก็บไฟล์ใหม่แยกจากฉบับก่อน รูปชิ้นงาน ป้าย แบรนด์ และหน้า PDF แนบใช้จากฉบับที่ใบผลิตนั้นอ้างอิง การเก็บหรือเปิดไฟล์ไม่เริ่มผลิต ไม่รับเงิน และไม่ส่งสินค้า

## QR และปุ่มพิมพ์เดิม

- QR ในไฟล์ใบเสนอราคาและใบรับเงิน ใช้ให้พนักงานที่เข้าสู่ระบบเปิดเอกสารตรงเลข/ฉบับ ใบผลิตใช้เปิดใบและฉบับนั้น
- ไฟล์ใบแจ้งหนี้ที่เก็บอัตโนมัติมาจากข้อมูลตอนยืนยันออเดอร์ ส่วน QR ติดตามที่เลือกเพิ่มตอนพิมพ์ ใช้ผ่านหน้าพิมพ์เดิม ระบบไม่สร้างลิงก์ลูกค้าใหม่ให้เองและไม่เก็บลิงก์ลับลงไฟล์อัตโนมัติ
- ปุ่ม Print เดิมยังใช้ตรวจรูปแบบหรือพิมพ์พร้อม QR ที่เลือกได้ ถ้าต้องการไฟล์ที่ระบบเก็บไว้แน่นอน ให้เลือก Download stored PDF
- ที่อยู่ localhost ใน QR เปิดได้เฉพาะเครื่องนั้น เมื่อใช้หลายอุปกรณ์ ต้องเปิดผ่านที่อยู่เว็บร้านที่เข้าถึงร่วมกัน
- เพิ่ม QR รับเงินธนาคารกีบ/บาทแล้ว เจ้าของตั้งค่าและตรวจผ่านแอปธนาคารก่อนเปิดใช้ ใบแจ้งหนี้ต้นฉบับใหม่เก็บ QR ที่เปิดไว้ ณ ตอนยืนยัน เปลี่ยนหรือปิดภายหลังไม่แก้ไฟล์เก่าและแจ้งข้อมูลปัจจุบันแยกบนเว็บ เอกสารก่อนมีส่วนนี้ไม่ถูกเติม QR ย้อนหลัง ดู [คู่มือ QR รับเงิน](PAYMENT_QR_TH.md) การสแกนไม่บันทึกเงินให้เอง

## เอกสารเดิมและการสำรอง

หลังอัปเกรด ระบบทยอยสร้างไฟล์ครั้งแรกจากข้อมูลแต่ละฉบับที่เคยเก็บไว้ ไม่เปลี่ยนชื่อ ราคา หรืออัตราแลกเปลี่ยนเป็นค่าปัจจุบัน เวลาที่เก็บไฟล์แสดงตามเวลาที่สร้าง PDF จริง ระบบไม่สามารถกู้ไฟล์ที่เคยบันทึกเองนอกโปรแกรมก่อนมีส่วนนี้กลับมาได้

รุ่นในเครื่องเก็บไฟล์ไว้ในฐานข้อมูลเดียวกับข้อมูลร้าน จึงรวมอยู่ในไฟล์สำรองที่มีรหัสผ่านและการทดลองกู้สำเนาแยกด้วย เมื่อเปิดสำเนากู้คืน ไฟล์ที่เก็บสำเร็จแล้วดาวน์โหลดได้ ส่วนสำเนากู้คืนยังไม่ทำงานเบื้องหลังอัตโนมัติตามกฎเดิม

ระบบสำรองอัตโนมัตินอกเครื่องและพื้นที่เก็บไฟล์บนบริการภายนอกยังเป็นงานต่อก่อนติดตั้งใช้งานจริง W10 ยังไม่เสร็จทั้งหมด

## ถ้าสร้างไฟล์ไม่ได้หลังเปิดโปรแกรมใหม่

เครื่อง Windows นี้ใช้ Microsoft Edge ที่ติดตั้งอยู่สร้าง PDF แบบเบื้องหลัง ไม่มีหน้าต่างให้พนักงานต้องควบคุมเอง ถ้าเปลี่ยนเครื่อง ผู้ติดตั้งต้องเตรียม Edge หรือ Chromium ให้ส่วนสร้างไฟล์ใช้ได้ แล้วลองใหม่ผ่านปุ่มเดิม ไม่ต้องล้างฐานหรือออกเลขเอกสารซ้ำ

สำหรับผู้ติดตั้ง: ระบุตำแหน่งเบราว์เซอร์ด้วย `JAZMINE_PDF_BROWSER` ได้ หรือใช้ Chromium ของ Playwright บนเครื่องปลายทาง ต้องสร้างแม่แบบด้วย `pnpm build:documents` ด้วย คำสั่ง `pnpm build:server` และตัวเปิดโหมดพัฒนาทำขั้นนี้ให้แล้ว ฐานข้อมูลภายนอกใช้ worker แยกตามวิธีเดิม

## ขอบเขตตามแผน

ผลตรวจรอบนี้: ชุดรวมผ่าน 112 กรณี รวมการสำรองกู้ไฟล์เดิม ทดลองการทำไฟล์เบื้องหลังและดาวน์โหลดผ่านเว็บจริงครบสี่ชนิด เปลี่ยนฉบับ/ยกเลิกรับเงินแล้วไฟล์เดิมตรงกันทุกส่วน ตรวจมือถือ 320/390 พิกเซล อ่าน QR จากภาพ PDF จริง และตรวจภาพเอกสารการค้าหนึ่งหน้า ใบผลิตรวมแนบสามหน้า และใบเสนอราคา 30 รายการห้าหน้า เส้นทางเดิมออเดอร์ ผลิต เงิน ส่ง ใบเสนอราคา และ QR ใบแจ้งหนี้ผ่านร่วมด้วย ตรวจรูปแบบและสร้างโปรแกรมผ่าน ใช้ข้อมูลจำลองแยกทั้งหมด

ใช้ W6 และ Phase 6 ข้อ 6C.18/6I เรื่องไฟล์ฉบับที่ออกแล้ว งานเบื้องหลัง และการลองเลข/ฉบับเดิม ร่วมกับ Phase 5 Final เรื่องเอกสารและ QR สำหรับการผลิตใช้ PS Version เดิม การคืนเงินไม่บังคับออกเอกสารตามที่เจ้าของกำหนด เป็นการทำตามแผน ไม่ใช่คำตัดสินทางธุรกิจใหม่ ต้นฉบับ Phase และไฟล์ซิงก์ไม่ถูกแก้
