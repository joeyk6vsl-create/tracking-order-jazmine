# ยกเลิกออเดอร์ จัดการยอดที่ตกลง และเก็บข้อมูลเก่า

เพิ่มสำเนาเอกสารพร้อมสถานะและตั้งค่าเก็บอัตโนมัติแล้ว ตาม [คู่มือล่าสุด](DOCUMENT_STATUS_AND_AUTO_ARCHIVE_TH.md) เจ้าของเลือกเปิดเองจาก Payments & delivery เริ่มปิดไว้และรอ 15 วันจากการตรวจพบว่าพร้อม ส่วน Archive ที่เจ้าของกดเองยังใช้ขั้นตอนในคู่มือนี้ ไม่มีการลบข้อมูลหรือย้อนการยกเลิกออเดอร์

ขั้นนี้ทำให้ยกเลิกงานได้โดยยังเปิดประวัติเดิม และให้เจ้าของเก็บออเดอร์ที่เคลียร์แล้วออกจากหน้าทำงานประจำได้ หน้าจอใช้ภาษาลาวผสมอังกฤษตามกฎของโครงการ

## เริ่มใช้งาน

ถ้ายังเปิดโปรแกรมรุ่นก่อนอยู่ ให้หยุดด้วย Ctrl+C เปิด `START_JAZMINE.cmd` ใหม่ แล้วรีเฟรชหน้าเว็บ ระบบเพิ่มที่เก็บข้อมูลใหม่เอง บัญชี ออเดอร์ เงิน และไฟล์เดิมยังอยู่ ไม่ต้องล้างข้อมูล

เข้า **Payments & delivery** เลือกออเดอร์ แล้วเปิด **Cancellation & archive → Review order effects** จะเห็นยอดรับสุทธิ จำนวนส่งแล้ว ใบผลิต งานที่กำลังทำ ปัญหาค้าง คำขอลูกค้า และรายการที่เตรียมส่ง

## ยกเลิกออเดอร์

1. เจ้าของหรือแอดมินตรวจเงิน ชิ้นงาน และการส่งที่เกี่ยวข้องก่อน
2. แจ้งผู้เกี่ยวข้องในร้านให้ทราบ โดยเฉพาะงานที่ยังทำอยู่ การเปลี่ยนสถานะในเว็บไม่ทำให้เครื่องจักรหรือคนหยุดงานเอง
3. เลือก **Cancel order** ติ๊กยืนยันตรวจผลกระทบ ใส่เหตุผล แล้วกด **Confirm cancel**
4. ตรวจสถานะ **Cancelled** และประวัติด้านล่าง เจ้าของจะต้องตัดสินยอดสุดท้ายแยกอีกครั้ง

หลังยกเลิก ระบบไม่รับคำสั่งเริ่ม/จบผลิตเพิ่มเติม ไม่ให้สร้างหรืออนุมัติใบผลิตใหม่ ไม่ให้สร้างงานทดแทน ใช้ต่องานข้ามฉบับ เตรียมส่ง หรือยืนยันส่งเพิ่ม และไม่ให้ยืนยันออเดอร์ฉบับใหม่จากร่างเดิม รายการที่เพียง **PREPARED** จะถูกยกเลิกพร้อมเหตุผลในครั้งเดียว ส่วนรายการที่ **CONFIRMED** แล้วคงอยู่ตามจริง

ใบผลิตที่ออกแล้ว ไฟล์ ชื่อ/เบอร์ ประวัติเริ่ม–จบ ของเสีย เงินรับ เงินคืน และใบแจ้งหนี้ฉบับเดิมยังอยู่ การยกเลิกไม่ลบข้อเท็จจริงที่เกิดขึ้นแล้ว และไม่คืนเงินหรือคืนวัตถุดิบเข้าคลังให้เอง

กราฟิกหรือเจ้าของยังเปิดตรวจและปิดใบผลิตที่ค้างได้ โดยใช้ลิงก์ใน **Review production sheets** ต้องตรวจชิ้นงานจริงก่อนปิด ใบที่ทำเสร็จแล้วไม่ต้องลบประวัติเพื่อเก็บออเดอร์ แอดมินยังจัดการปัญหาที่ค้างและแก้บันทึกจำนวนตามขั้นเดิมได้ แต่สร้างงานทดแทนเพิ่มจากออเดอร์ที่ยกเลิกไม่ได้

## ตกลงยอดหลังยกเลิก — เจ้าของเท่านั้น

ระบบไม่เดาว่าคืนเงินทั้งหมดหรือร้านเก็บทั้งหมด แม้ไม่มีเงินรับก็ต้องให้เจ้าของระบุข้อตกลงก่อนเก็บออเดอร์ ยอดที่ยังไม่ตัดสินจะแสดง **Pending agreement** หรือ **Owner decision required** และยังไม่เปิดรับเงินเพิ่ม การแก้รายการรับเงินเดิมและคืนเงินจริงตามสิทธิ์ยังทำได้

1. เจ้าของเปิดออเดอร์เดิมแล้วเลือก **Record cancellation agreement**
2. กรอก **Agreed final amount** เป็นจำนวนกีบเต็ม หมายถึง “ยอดสุดท้ายทั้งหมดที่ตกลงให้ร้านได้รับ” ไม่ใช่จำนวนที่จะคืน ไม่ต้องลบราคาเดิมของออเดอร์
3. ตรวจตัวอย่างยอดที่จะคืนหรือรับเพิ่มบนหน้าจอ ใส่เหตุผล ติ๊กตรวจผลกระทบ แล้วกด **Confirm agreement**
4. ถ้ามี **Refund due** ให้ใช้ปุ่ม **Refund** ที่รายการรับเงินเดิมเพื่อบันทึกการคืนจริง ถ้ามี **Additional due** ให้บันทึกรับเงินตามช่องทางจริง การบันทึกข้อตกลงอย่างเดียวยังไม่ทำรายการเงิน
5. เมื่อยอดรับสุทธิเท่ากับที่ตกลง จะแสดง **Finances clear** ถ้าต้องแก้ข้อตกลงภายหลัง เจ้าของบันทึกยอดใหม่พร้อมเหตุผล ระบบเก็บทุกฉบับไว้

ตัวอย่าง รับมาแล้ว 800,000 กีบ ตกลงให้ร้านได้รับสุดท้าย 300,000 กีบ ให้กรอก 300,000 ระบบแสดงต้องคืน 500,000 กีบ จากนั้นเจ้าของจึงบันทึกคืนจริง 500,000 กีบ เมื่อคืนครบจะเคลียร์ตามข้อตกลง ถ้าตกลงให้ร้านเก็บเงินที่รับมาแล้วทั้งหมด ต้องระบุยอดนั้นเอง ไม่ถือว่าเก็บให้อัตโนมัติ

การคืนเงินจริงยังใช้สิทธิ์เดิม: เจ้าของทำได้ แอดมินทำไม่ได้ รองรับคืนเต็มหรือบางส่วนตามวงเงินของใบรับเงิน ใช้สกุลและอัตราของใบเดิม ส่วนยอดตกลงหลังยกเลิกใช้ LAK กลางเพื่อเทียบยอดทั้งหมด

## เก็บออเดอร์เก่าออกจากหน้าทำงาน

เจ้าของเลือก **Archive order** ตรวจเหตุผลที่ยังเก็บไม่ได้ ถ้าเงื่อนไขครบจึงติ๊กตรวจ ใส่เหตุผล แล้วกด **Confirm archive**

| ออเดอร์    | เก็บได้เมื่อ                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| งานปกติ    | ส่งครบ เงินครบ ไม่มีปัญหาผลิตหรือคำขอลูกค้าค้าง ไม่มีรายการเตรียมส่งหรือใบผลิตที่ยังไม่เสร็จ และพ้น 15 วันหลังส่งครบ โดยไม่เร็วกว่าวันยืนยันฉบับล่าสุด |
| ยกเลิกแล้ว | เจ้าของระบุข้อตกลงและจัดการเงินจริงจนเคลียร์แล้ว ไม่มีปัญหาหรือคำขอค้าง ไม่มีรายการเตรียมส่ง และปิดใบผลิตที่ยังไม่เสร็จหลังตรวจชิ้นงานแล้ว             |

การเก็บแยกจากการยกเลิก ออเดอร์ปกติที่เก็บแล้วยังนับยอดขายย้อนหลัง ออเดอร์ยกเลิกที่เก็บแล้วก็ยังเป็นออเดอร์ยกเลิก ไม่ใช่การลบข้อมูล

ออเดอร์ที่เก็บแล้วจะไม่อยู่ในรายการทำงานประจำของร่าง งานกราฟิก เตรียมผลิต คิวผลิต ออเดอร์ยืนยัน และรายการรับเงินเริ่มต้น ถ้าต้องค้น ให้ใช้ **Search** หรือเปิด **Include archived orders** ในหน้า Payments & delivery แล้วค้นชื่อ/เลขออเดอร์ เปิดดูเอกสาร เงิน งานผลิต และประวัติเดิมได้

เจ้าของเลือก **Restore to working lists** เพื่อแสดงกลับในรายการทำงาน การเปิดกลับไม่ย้อนการยกเลิกออเดอร์ ถ้ามีการบันทึกเงิน การแก้ประวัติงาน หรือคำถามลูกค้าใหม่หลังเก็บ ระบบเปิดกลับมาให้ตรวจงานและบันทึกเหตุผลอัตโนมัติ สถานะยกเลิกเดิมยังอยู่

## รายงานและหน้าลูกค้า

- ออเดอร์ยกเลิกไม่นับยอดขาย จำนวนออเดอร์ขาย หรือจำนวนสินค้าที่ต้องผลิตในรายงานยอดปัจจุบัน แต่รายการรับ/คืนเงินจริงยังนับตามเดิม ประวัติการผลิตจริงยังอยู่
- ยอดค้างหลังยกเลิกคิดจากยอดสุดท้ายที่เจ้าของตกลง ถ้ายังไม่ตกลง รายงานแยกจำนวนเรื่องที่รอตัดสิน ไม่อ้างว่ายอดที่ไม่รู้เป็นเงินค้างศูนย์
- รายงานย้อนหลังใช้ข้อมูลที่ระบบรู้ ณ สิ้นวันนั้น การยกเลิกหรือแก้ข้อตกลงภายหลังไม่เขียนทับภาระที่มีในวันก่อน
- แถวออเดอร์ยกเลิกยังแสดงราคาเดิมไว้ตรวจประวัติพร้อมป้ายว่าไม่รวมยอดขาย ออเดอร์ปกติที่เก็บแล้วไม่ถูกตัดออกจากยอดขายย้อนหลัง
- ลูกค้าที่ยืนยันเบอร์กับลิงก์แล้วเห็นสถานะยกเลิกและให้ติดต่อร้าน ไม่เห็นยอดข้อตกลงภายในหรือเหตุผลภายใน ขอส่ง/เร่งงานเพิ่มไม่ได้ แต่ยังส่งคำถามทั่วไปได้ คำถามใหม่เปิดรายการเก่ากลับให้ร้านตรวจ

## ถ้าข้อมูลเปลี่ยนหรือการเชื่อมต่อขาด

ถ้ามีคนรับเงิน เปลี่ยนงาน หรือส่งสินค้าระหว่างตรวจ ระบบจะให้ **Reload order effects** แล้วตรวจใหม่ก่อนรับการยืนยัน ถ้าขาดการเชื่อมต่อหลังกด ให้ใช้ **Retry** ในฟอร์มเดิม คำขอเดิมจะไม่ยกเลิกหรือเก็บข้อมูลซ้ำ

## ขอบเขตของรุ่นนี้

ยังไม่มีการลบถาวร การทำเครื่องหมายออเดอร์ผิด/ซ้ำ (**VOIDED**) หรือย้อนการยกเลิกออเดอร์ เพิ่มสำเนาเอกสารพร้อมสถานะและเก็บอัตโนมัติที่เจ้าของเลือกเปิดแล้ว ดู [คู่มือล่าสุด](DOCUMENT_STATUS_AND_AUTO_ARCHIVE_TH.md) ต้นฉบับยังอยู่ครบ เจ้าของยังกดเก็บเองตามเงื่อนไขเดิมได้ การเปิดกลับไม่ย้อนการยกเลิก

เงื่อนไขอ้างจาก Phase 0 เรื่อง Cancel/Archive, Phase 3 เรื่องยอดหลังยกเลิก รายงานและการเก็บ และ Phase 6 เรื่องแยกสถานะงานกับสถานะเก็บ พร้อมสิทธิ์เจ้าของที่ยืนยันไว้ ใช้ Phase 5 Final แทนฉบับเก่า หากต้องตัดสินข้อขัดแย้ง ให้ตรวจตามลำดับ Phase 0 → 1 → 2 → 3 → 4 → 5 Final → 6 แล้วเทียบคำตัดสินล่าสุดของเจ้าของ ในขั้นนี้ไม่มีการแก้เอกสาร Phase ต้นฉบับ

ตรวจรวมผ่าน 91 กรณี รวม 7 กลุ่มของวงจรใหม่นี้ ตรวจรูปแบบและสร้างโปรแกรมผ่าน และตรวจเบราว์เซอร์ร่วมกับเส้นทางออเดอร์/ผลิต/เงิน/ส่งเดิม รวมหน้าลูกค้า รายงาน และค้นหาแล้ว

ใช้แนวทาง verification ตรวจเรื่องเดียวกันตั้งแต่หน้ารับเงิน → คำขอยกเลิก/ข้อตกลง/เก็บ → ข้อมูลที่บันทึก → การแสดงกลับ ไม่ใช้เพียงผลว่าหน้าเปิดได้

| จุดตรวจ                    | ผลและหลักฐาน                                                                                       |
| -------------------------- | -------------------------------------------------------------------------------------------------- |
| หน้าจอแสดงและกดได้         | เบราว์เซอร์ทดสอบผ่านทั้ง ADMIN และเจ้าของ ภาพคอม/มือถือข้างต้น ไม่มีข้อผิดพลาดหน้าจอ               |
| หน้าจอส่งคำขอถูกต้อง       | คำขอยกเลิกตอบ 201 แล้วจำลองขาดการเชื่อมต่อ การกดลองคำขอเดิมไม่เพิ่มการยกเลิกซ้ำ                    |
| ข้อมูลถูกบันทึก            | ตรวจรายการเงินสุทธิหลังคืนจริง สถานะรายการเตรียมส่ง และจำนวนประวัติในฐานจำลอง                      |
| แสดงผลกลับครบ              | หน้าจอแสดง Finances clear, เก็บออกจากรายการประจำ, เปิดข้อมูลเก่า และ Restore โดยยัง Cancelled      |
| สิทธิ์และข้อมูลที่สัมพันธ์ | พนักงานถูกปฏิเสธการจัดการออเดอร์ งานผลิตเริ่ม/จบเพิ่มไม่ได้ รายงานและหน้าลูกค้าผ่านชุดเดิมร่วมด้วย |
