# ผลตรวจระบบลูกค้าประจำ รุ่น 0.2

## ทำอะไรได้แล้ว

เจ้าของและพนักงานแผนก ADMIN มีเมนูลูกค้าประจำ เพิ่มชื่อ เบอร์ กลุ่มราคา แบรนด์ วันที่เริ่มเป็นลูกค้า และหมายเหตุได้ ค้นจากขึ้นต้นชื่อหรือเบอร์ กรองสถานะ และเปลี่ยนหน้าได้

ข้อมูลเก็บในฐานข้อมูลจริง เจ้าของเปลี่ยนสถานะใช้งาน/ปิดใช้งานได้ พนักงานฝ่ายผลิตไม่มีสิทธิ์อ่านหรือแก้รายชื่อจาก API นี้

## การตรวจรอบนี้

- ชุดหลังบ้านรวม 26 กรณี: บัญชีและสิทธิ์เดิม 15 กรณี + ลูกค้า 11 กรณี
- เพิ่มโครงสร้างลูกค้าลงฐานรุ่น 0.1 โดยบัญชีเดิมยังอยู่และเข้าสู่ระบบได้
- เบอร์ซ้ำอนุญาตให้เป็นหลายราย/หลายแบรนด์ และคืนคำเตือนโดยไม่รวมคนอัตโนมัติ
- กดบันทึกคำขอเดียวกันพร้อมกันหรือส่งซ้ำ ได้รายชื่อเดียวและประวัติสร้างเพียงครั้งเดียว
- คำขอเดิมแต่เปลี่ยนข้อมูลถูกปฏิเสธ ไม่เขียนทับผลเดิม
- แก้ลูกค้าโดยใช้ฉบับเก่าถูกปฏิเสธ และเก็บก่อน/หลังการแก้
- เจ้าของเปลี่ยนสถานะรายชื่อได้ ส่วน ADMIN เปลี่ยนสถานะไม่ได้
- ไม่มีเส้นทางลบลูกค้าถาวร
- ค้นหาเป็นข้อความจริง ไม่ตีความเครื่องหมายเปอร์เซ็นต์เป็นการค้นทุกคน
- แบ่งหน้าข้อมูลไม่ซ้ำข้ามหน้า และจำกัดจำนวนข้อมูลที่ดึง
- วันที่ เบอร์ และกลุ่มราคาที่ไม่ถูกต้องถูกปฏิเสธ
- ย้ายพนักงาน ADMIN ออกไปแผนกอื่นแล้ว การเข้าสู่ระบบเก่าใช้ดูลูกค้าต่อไม่ได้
- ทดลองผ่านเบราว์เซอร์จริง: เพิ่ม → จำลองการเชื่อมต่อขาดหลังบันทึก → ลองคำขอเดิม → แก้ → ค้นด้วยเบอร์ → บันทึกอีกแบรนด์ที่เบอร์ซ้ำ
- ตรวจหน้ารายชื่อและรายละเอียดบนคอมพิวเตอร์และความกว้าง 320/390 พิกเซล
- ตรวจชนิดข้อมูล รูปแบบโค้ด และ build ของโปรแกรม

## ขอบเขตที่ยังไม่พร้อม

- ยังไม่มีออเดอร์จริง ลูกค้าขาจรจึงยังไม่ต้องนำมาเพิ่มในรายชื่อประจำ จะมีแบบฟอร์มเฉพาะออเดอร์ในช่วงถัดไป
- ชื่อแบรนด์ยังไม่ได้เชื่อมไฟล์ป้ายคอ/เทปคอ การบันทึกข้อมูลครั้งนี้ไม่หมายความว่าไฟล์พร้อมผลิต
- ยังไม่มีประวัติออเดอร์ ยอดค้าง หรือรายงานลูกค้าที่คำนวณจากรายการจริง
- ตรวจฐาน PGlite ในเครื่อง ยังไม่ได้ตรวจการเชื่อม PostgreSQL ภายนอก
- ปรับหน้าจอเป็นภาษาลาวครบทุกข้อความและฟอนต์ Noto Sans Lao ทั้งระบบเป็นงาน UI ที่เจ้าของยอมให้เก็บภายหลัง

ใช้ข้อมูลทดสอบแยกจากฐานของเจ้าของ ไม่ได้เพิ่มลูกค้าทดสอบลง `local-data/postgres` ที่เจ้าของใช้ทดลอง
