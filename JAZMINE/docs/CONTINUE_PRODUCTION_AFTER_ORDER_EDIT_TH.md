# ใช้งานผลิตเดิมต่อหลังแก้ออเดอร์ — คู่มือ JAZMINE

เมื่อออเดอร์ยืนยันเป็นฉบับใหม่แล้ว เจ้าของหรือแอดมินทบทวนได้ว่างานเดิมจำนวนไหนใช้ต่อ จำนวนไหนไม่ใช้กับฉบับนี้ ระบบสร้างร่างใบผลิตใหม่ให้กราฟิกหรือเจ้าของตรวจอนุมัติ แล้วจึงนำสถานะงานที่ทำแล้วมาใช้ต่อ ใบเก่า ไฟล์เก่า และประวัติเดิมยังอยู่ครบ

## ใครทำขั้นตอนไหน

| งาน                                     | ผู้ทำ                                                  |
| --------------------------------------- | ------------------------------------------------------ |
| แก้และยืนยันออเดอร์ฉบับใหม่             | เจ้าของ / ADMIN                                        |
| เลือกจำนวนใช้ต่อและยืนยันแผน            | เจ้าของ / ADMIN                                        |
| ตรวจไฟล์และทำใบผลิตใหม่ให้พร้อม         | GRAPHIC / เจ้าของ                                      |
| ทำงานต่อหลังใบใหม่พร้อม                 | พนักงานแต่ละแผนกตามสิทธิ์เดิม                          |
| รับเงิน แก้รายการ คืนเงิน หรือส่งสินค้า | ใช้เมนูและสิทธิ์เดิม การทบทวนผลิตไม่ทำรายการเงินให้เอง |

ADMIN เลือกจำนวนได้ แต่ไม่สามารถข้ามขั้นอนุมัติใบผลิตของกราฟิกได้ แบบใหม่ที่ต้องอนุมัติไฟล์ก็ยังใช้ขั้นกราฟิกตามปกติ

## วิธีทำทีละขั้น

1. แก้ร่างออเดอร์ ใส่เหตุผล ตรวจไฟล์กับกราฟิก และยืนยันเป็นออเดอร์ฉบับใหม่ตามขั้นตอนเดิม
2. เปิดเมนู **เตรียมใบผลิต** เลือกออเดอร์นั้น แล้วเลื่อนมาที่ **Review previous production**
3. ตรวจทุกใบเก่าที่แสดง ดูจำนวนที่จัดไว้ ของเสีย จำนวนที่ปล่อยคืน จำนวนที่ส่งแล้ว และจำนวนที่เหลือ เลือกรายการ/ไซซ์ในออเดอร์ใหม่ที่จะใช้ต่อ แล้วกรอกจำนวน **Reuse quantity** ค่าเริ่มต้นเป็นศูนย์ ต้องเลือกเอง
4. หากมีชื่อและเบอร์ ให้เปิด **Retained names & numbers** และเลือกเฉพาะคนที่นำงานมาใช้ต่อจริง โดยตรวจด้วยว่าเป็นชิ้นที่ยังไม่ส่งและไม่ใช่ของเสีย
5. ตรวจยอดรวม “ใช้ต่อ / ไม่ใช้กับฉบับนี้” ให้ครบทุกใบ ใส่เหตุผล และทำเครื่องหมายยืนยันทั้งการตรวจไฟล์/งานเดิมและการตรวจจำนวน
6. กด **Confirm production review** ระบบปิดใบเก่าที่ทบทวน เก็บประวัติ และสร้างร่างใบใหม่ตามจำนวนที่เลือก ส่วนจำนวนที่ไม่เลือกจะไม่ถูกนับเป็นงานของฉบับใหม่
7. ให้ **GRAPHIC หรือเจ้าของ** เปิดร่างใบใหม่จากประวัติหรือรายการใบผลิต ตรวจแบบ ผ้า ไซซ์ ชื่อ/เบอร์ ไฟล์และจำนวน ใส่เหตุผล แล้วกด **ตรวจครบแล้ว ทำใบผลิตให้พร้อม**
8. หลังอนุมัติ ให้ฝ่ายผลิตเปิด **Work queue** และกด Refresh งานใหม่จะบอกว่าใช้ต่อจากใบไหน แผนกที่จบแล้วคงสถานะจบ แผนกที่กำลังทำยังเป็นงานกำลังทำ ส่วนที่ยังไม่เริ่มยังต้องเริ่มตามปกติ
9. หากออเดอร์ยังมีจำนวนที่ขาด ให้กราฟิกเตรียมใบผลิตเพิ่มตามปกติ งานเพิ่มเริ่มใหม่ ไม่ได้รับสถานะเสร็จจากใบที่ใช้ต่อ

ระหว่างรอกราฟิก ใบใหม่ยังไม่นับเป็นสินค้าพร้อมส่ง คิวฝ่ายผลิตมีข้อความ **Continued work awaiting graphic approval** หลังอนุมัติจึงใช้ใบใหม่ทำต่อ ข้อความนี้อยู่ในระบบและเห็นเมื่อเปิดหรือ Refresh คิวงาน ไม่ได้ส่งข้อความออกไปหาพนักงานนอกระบบ

ใบที่ปิดแล้วแสดงสถานะยกเลิกเพื่อหยุดการใช้คำสั่งเก่า การปิดใบไม่ได้ลบงานหรือแปลว่าสินค้าทุกชิ้นเป็นของเสีย จำนวนที่ใช้ต่อและที่ไม่ใช้ถูกบันทึกแยกไว้พร้อมผู้ทบทวนและเหตุผล

## ตัวอย่างที่ตรวจแล้ว

ออเดอร์เดิม 11 ตัว ผลิตเสร็จและผ่าน QC ส่งไปแล้ว 3 ตัว ต่อมาลูกค้าเพิ่มยอดรวมเป็น 15 ตัว:

- งานเดิมเหลือใช้ต่อได้ 8 ตัว ไม่เอา 3 ตัวที่ส่งแล้วมานับเป็นพร้อมส่งอีก
- เจ้าของ/ADMIN เลือกใช้ต่อ 8 ตัว แล้วให้กราฟิกหรือเจ้าของตรวจใบใหม่
- หลังอนุมัติ ใบที่ใช้ต่อมีพร้อมส่ง 8 ตัว และยังมีประวัติส่งแล้ว 3 ตัว
- อีก 4 ตัวต้องมีใบผลิตเพิ่มและผ่านขั้นตอนผลิต/QC ใหม่
- เมื่อส่งครบทั้งสองชุด ยอดส่งรวมเป็น 15 ตัว การลองคำขอเดิมซ้ำไม่เพิ่มจำนวนหรือเลขใบผลิตซ้ำ

ถ้าเดิมพิมพ์เสร็จแต่กำลังรีด ใบที่ใช้ต่อหลังอนุมัติจะยังเป็น “พิมพ์เสร็จ / รีดกำลังทำ” ไม่เปลี่ยนทุกแผนกให้เสร็จเอง เวลาที่เริ่มและจบงานเดิมยังอ้างอิงเวลาที่ทำจริง

| ใบเก่ากำลังแก้และยังไม่พร้อม                        | ตรวจงานเก่าให้ชัดเจน หรือเลือกไม่ใช้กับฉบับใหม่ ระบบไม่เดาสถานะจากร่าง                        |

| เลือกเกินจำนวนที่เหลือหรือออเดอร์ใหม่               | ลดจำนวนที่ใช้ต่อ ระบบไม่นับของเสีย จำนวนปล่อยคืน หรือของที่ส่งแล้วซ้ำ                         |
| ชื่อ/เบอร์ที่เลือกไม่ตรงกับจำนวน                    | ตรวจชิ้นงานจริงและเลือกรายชื่อใหม่ ระบบไม่เลือกแทนให้                                         |
| ข้อมูลเปลี่ยนระหว่างเปิดหน้าทบทวน                   | ใช้ **Reload review** ตรวจรายการล่าสุดก่อนยืนยันใหม่                                          |
| แก้จำนวน ชื่อ คำสั่งงาน หรือไฟล์หลังยืนยันแผนใช้ต่อ | ระบบไม่ยกสถานะเดิมไปกับคำสั่งที่เปลี่ยน ต้องตรวจให้ตรงแผนเดิม หรือยกเลิกร่างและเตรียมผลิตใหม่ |

หากการเชื่อมต่อขาดหลังกดยืนยัน ให้กด **Retry production review** ซึ่งใช้คำขอเดิม ระบบคืนผลที่บันทึกแล้วและไม่สร้างร่างซ้ำ หากปิดหน้าไปแล้ว สามารถดูรายการที่ทำสำเร็จในประวัติได้

หากมีรายการ **เตรียมส่ง** จากออเดอร์ฉบับเก่า ต้องตรวจและยกเลิกรายการที่ไม่ใช้ใน **Payments & delivery** ก่อนเตรียมส่งใหม่ ระบบไม่ยืนยันส่งจากออเดอร์ฉบับเก่าให้เอง ประวัติการส่งที่ยืนยันแล้วคงเดิม

## ข้อมูลใดคงอยู่

ใบผลิตเก่าทุกฉบับ ไฟล์ ชื่อ/เบอร์ รายงานปัญหา จำนวนเสีย และประวัติเริ่ม–จบงานยังอยู่เดิม ใบใหม่มีข้อมูลออเดอร์ปัจจุบันและบอก **Continued from** ในหน้าทำงานและใบพิมพ์ PDF ไฟล์ที่เนื้อหาเดิมอ้างอิงข้อมูลภาพเดิม จึงไม่เก็บภาพซ้ำทุกครั้งที่เปลี่ยนฉบับ

การเลือก “ไม่ใช้กับฉบับนี้” ไม่ได้คืนวัตถุดิบเข้าสต็อก ไม่ตัดเป็นของเสียหรือสร้างต้นทุนให้อัตโนมัติ เพิ่มปุ่มตรวจและย้อนแผนที่ยืนยันแล้วทั้งชุดในขั้นถัดมาแล้ว ใช้เมื่อยังไม่มีงานต่อเนื่องที่ขัดกันและมีข้อมูลสถานะก่อนปิดครบ ดู [คู่มือย้อนแผนทั้งชุด](REVERSE_PRODUCTION_REUSE_PLAN_TH.md) แผนเก่าที่ไม่มีหลักฐานครบยังต้องตรวจด้วยคน

ยอดเงินค้างยังใช้ราคาออเดอร์ล่าสุดกับเงินรับสุทธิเดิม หากมีเงินรับเกิน เจ้าของต้องพิจารณาคืนเงินผ่านขั้นตอนเดิม ไม่มีการรับหรือคืนเงินโดยหน้าทบทวนการผลิต

## ขอบเขตและงานถัดไป

ผลตรวจรอบนี้: ชุดรวม **75 กรณีผ่าน** รวม 7 กลุ่มตรวจใหม่ของการใช้ต่อ เส้นทางหน้าจอแอดมิน → กราฟิก → ฝ่ายผลิตผ่าน รวมการลองคำขอเดิมหลังการเชื่อมต่อขาด มือถือ 320/390px และใบผลิตมาตรฐาน A4 สองหน้าที่มีข้อความที่มาของงาน ตรวจสร้างโปรแกรมและตรวจรูปแบบโค้ดผ่าน งานเดิมตั้งแต่ออเดอร์จนถึงรับเงินและส่งสินค้ายังผ่าน ตัวอย่างที่มีข้อมูลยาวหรือเอกสารแนบหลายหน้ามีหน้าต่อเนื่องตามกติกาเดิม ไม่จำกัดทุกใบไว้สองหน้า

ทบทวนทุกใบเก่าที่ยังเปิดของออเดอร์พร้อมกันได้สูงสุด 100 ใบ การบันทึกสำเร็จครบชุดหรือไม่เปลี่ยนอะไรทั้งชุด หนึ่งรายการเก่าเลือกไปยังหนึ่งรายการใหม่ต่อใบในรอบนี้ หากต้องแบ่งรายการเก่ารายการเดียวไปหลายรายการใหม่ ต้องตรวจแผนจำนวนเพิ่มเติมก่อน

การใช้ต่อแยกจากการสร้างออเดอร์ฉบับใหม่ และแยกจากการออกใบผลิตฉบับแก้ไขภายในออเดอร์เดิม ระบบไม่ยกสถานะเสร็จข้ามคำสั่งผลิตที่เปลี่ยนอัตโนมัติ เพิ่มการแก้จำนวนปัญหาที่ปิดผิดพร้อมประวัติแล้ว ดู `CORRECT_PRODUCTION_ISSUE_QUANTITIES_TH.md` จำนวนที่ใช้ต่อไปแล้วยังถูกป้องกัน และการแก้ใบเก่าไม่เพิ่มสินค้าเข้าใบใหม่ให้เอง ยังเหลือการยกเลิกออเดอร์/เก็บถาวร งานค้างอื่นตามแผน การทดลองกับแต่ละแผนกบนอุปกรณ์จริง สำรองอัตโนมัติ และข้อมูลต้นทุนก่อนคำนวณกำไร

เพิ่มการแก้จำนวนปัญหาที่ปิดผิดและการย้อนแผนใช้ต่อทั้งชุดแล้ว ดู `CORRECT_PRODUCTION_ISSUE_QUANTITIES_TH.md` และ `REVERSE_PRODUCTION_REUSE_PLAN_TH.md` ผลตรวจ 75 กรณีด้านบนเป็นประวัติรอบเริ่มส่วนใช้ต่อ งานค้างปัจจุบันให้ดู `../DEVELOPMENT_STATUS_TH.md` ยังต้องจัดชุดทดลองงานจริงรายแผนก
