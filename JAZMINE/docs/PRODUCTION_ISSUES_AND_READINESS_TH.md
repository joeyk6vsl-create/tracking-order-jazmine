# ปัญหาการผลิต ของเสีย งานทดแทน และจำนวนพร้อมส่ง

ปรับปรุงล่าสุด: เพิ่ม **Correct recorded quantities** สำหรับเจ้าของ/ADMIN แก้จำนวนหลังปิดปัญหาแล้วพร้อมประวัติ ดู `CORRECT_PRODUCTION_ISSUE_QUANTITIES_TH.md` ส่วนการใช้ต่องานหลังแก้ออเดอร์ดู `CONTINUE_PRODUCTION_AFTER_ORDER_EDIT_TH.md` และงานรับเงิน/ส่งสินค้าเพิ่มแล้วใน `PAYMENTS_AND_DELIVERY_TH.md` บันทึกผลทดสอบท้ายเอกสารนี้เป็นรอบแรกของส่วนปัญหา

## เริ่มใช้งานตรงไหน

หยุดโปรแกรมเดิมด้วย Ctrl+C แล้วเปิด `START_JAZMINE.cmd` ใหม่ ใช้บัญชีเดิม เข้า **ວຽກຜະລິດ / Work queue** แล้วเปิดใบผลิต จะมีส่วน **ປັນຫາ / Production issues** ใต้สถานะแผนก หน้าจอส่วนใหม่นี้ใช้ภาษาลาวผสมอังกฤษ

## พนักงานแจ้งปัญหา

1. เลือกประเภท: งานเสีย วัสดุ แบบงาน เครื่องจักร หรือเรื่องอื่น
2. เลือก **Continue** เพื่อรายงานและทำงานต่อ หรือ **Stop** เพื่อรายงานและหยุดส่วนที่เกี่ยวข้อง
3. อธิบายสิ่งที่พบ จุดที่เกิด และสาเหตุถ้าทราบ ถ้าเป็นงานเสีย ต้องระบุไซซ์และจำนวนที่พบ
4. กด Report ระบบเก็บผู้แจ้ง เวลา แผนก และฉบับใบผลิต

จำนวนที่พนักงานกรอกเป็นจำนวนที่พบปัญหา ยังไม่ใช่การยืนยันตัดของเสียหรือเพิ่มยอดผลิต พนักงานแจ้งได้เฉพาะแผนกของตน เจ้าของและแอดมินแจ้งแทนได้

**Continue** ไม่หยุดปุ่มทำงาน ขั้นตอนเริ่ม–จบยังใช้กฎเดิม แต่ใบที่มีปัญหาค้างจะยังไม่ส่งจำนวนเข้าในยอดพร้อมส่งจนกว่าจะตรวจและปิดปัญหา

**Stop** หยุดการเริ่ม/จบของแผนกที่แจ้งและแผนกถัดจากนั้นในใบผลิตเดียวกัน ขั้นก่อนหน้ายังทำต่อได้ สถานะงานและประวัติที่ทำไปแล้วไม่ถูกลบ เมื่อเจ้าของหรือแอดมินปิดปัญหาแล้วจึงทำต่อได้ หากมีหลายปัญหาที่สั่งหยุด ต้องปิดปัญหาที่เกี่ยวข้องให้ครบ

ปัญหาค้างยังอยู่ในคิว Active แม้งานแผนกจะทำเสร็จ หรือใบผลิตถูกยกเลิกแล้ว เพื่อให้ผู้รับผิดชอบตามปิดบันทึกได้ ใบที่ยกเลิกแล้วไม่สามารถเริ่มผลิตต่อจากปุ่มนี้

## เจ้าของหรือแอดมินตรวจและปิดปัญหา

ทั้งสองฝ่ายจัดการปัญหาได้ทุกประเภท พนักงานฝ่ายผลิตไม่มีปุ่มยืนยันจำนวนหรือปิดปัญหา

สำหรับแต่ละไซซ์ที่รายงาน ให้แบ่งจำนวนออกเป็นสี่ช่อง:

| ช่อง    | ความหมาย                                                     |
| ------- | ------------------------------------------------------------ |
| Usable  | จำนวนจากกลุ่มที่รายงานซึ่งตรวจแล้วใช้ได้                     |
| Scrap   | จำนวนเสียหรือตำหนิที่ใช้ไม่ได้                               |
| Release | จำนวนที่ยังไม่ได้ทำและปล่อยออกจากชุดนี้เพื่อจัดใหม่          |
| Dismiss | จำนวนที่รายงานซ้ำหรือไม่ใช่ปัญหาของชุดนี้ ต้องอธิบายในเหตุผล |

**สี่ช่องนี้รวมกันต้องเท่ากับจำนวนที่รายงาน** และห้ามนำจำนวนที่เคยตัดไปแล้วมาตัดซ้ำจนเกินของที่เหลือในใบผลิต

ช่อง **Replacement** แยกต่างหาก ใช้ระบุจำนวนที่จะสร้างร่างผลิตทดแทน ต้องไม่เกิน Scrap + Release ของรายการนั้น มีปุ่ม **Replace all affected** สำหรับกรณีตรวจแล้วเสียทั้งหมดและต้องผลิตชดเชยทั้งหมด

ใส่เหตุผลก่อนกด Resolve ถ้าเป็นเรื่องเครื่องจักรหรือเรื่องทั่วไปที่ไม่มีจำนวนเสื้อ ก็ปิดพร้อมเหตุผลได้โดยไม่สร้างของเสียสมมติ

ตัวอย่าง: PS จัดไว้ 100 ตัว พบเสีย 5 ตัว ให้รายงานเฉพาะ 5 ตัว แล้วแบ่งเป็น Usable 0, Scrap 5, Release 0, Dismiss 0 และ Replacement 5 ส่วนอีก 95 ตัวไม่ได้ถูกรายงานเสีย จึงยังอยู่ในจำนวนสุทธิของชุดเดิม แต่ยังต้องผ่าน QC

## งานผลิตทดแทน

เมื่อยืนยัน Replacement ระบบสร้าง **Draft PS ใหม่** ใต้ออเดอร์เดิม พร้อมลิงก์กลับไปยังปัญหาและฉบับต้นทาง ไม่เพิ่มจำนวนที่ลูกค้าสั่ง ไม่สร้างออเดอร์หรือใบแจ้งหนี้ใหม่

เปิดลิงก์ Replacement เพื่อให้เจ้าของหรือกราฟิกตรวจแบบ ผ้า ไซซ์ ชื่อ/เบอร์ และแนบไฟล์ให้ครบก่อนทำ PS ให้พร้อม ระบบไม่คัดลอกไฟล์เก่าให้ถือว่าพร้อมอัตโนมัติ เพราะไฟล์เดิมอาจเป็นสาเหตุของปัญหา งานทดแทนต้องผ่านทั้งหกแผนกและ QC เช่นเดียวกับงานปกติ

หากสร้างเพียงบางส่วนก่อน จะมีช่องสร้างทดแทนเพิ่มตามสิทธิ์ที่ยังเหลือ ร่างที่สร้างไว้แล้วก็นับว่าได้จัดจำนวนไปแล้ว การกดซ้ำไม่เพิ่มร่างใหม่ หากยกเลิกร่างทดแทน จำนวนที่ยกเลิกจึงนำมาจัดใหม่ได้ โดยยังต้องไม่เกินออเดอร์

ถ้างานทดแทนเสียอีก ให้แจ้งปัญหาที่ PS ทดแทนใบนั้นและสร้างงานชดเชยที่เชื่อมต่อกัน ไม่ใช้ปัญหาเดิมเพิ่มจำนวนซ้ำโดยไม่มีหลักฐาน

## ดูจำนวนพร้อมส่ง

เจ้าของและแอดมินเห็นส่วน **Readiness** ของออเดอร์ฉบับปัจจุบัน แยกตามไซซ์:

- Order: จำนวนตามออเดอร์ รวมของแถม
- Allocated (net): จำนวนจัดผลิตสุทธิหลังหัก Scrap และ Release รวมร่างที่จองจำนวนไว้แล้ว
- Ready: จำนวนสุทธิจาก PS ที่พร้อม มี QC Complete ในฉบับปัจจุบัน และไม่มีปัญหาค้างของใบนั้น
- Scrap / Release: จำนวนที่ยืนยันไว้ของออเดอร์ฉบับปัจจุบัน รวมบันทึกจากใบที่ยกเลิกแล้ว ประวัติของออเดอร์ฉบับเก่ายังเก็บแยกไว้ ไม่เอาไซซ์จากฉบับเก่ามาปนกับฉบับใหม่

สถานะเป็น Not ready, Partially ready หรือ Ready to ship ตามจำนวนที่ผ่านเงื่อนไข **Usable ไม่ทำให้พร้อมส่งเอง และ Ready to ship ไม่ใช่ Shipped**

ตัวอย่าง PS เดิม 100 ตัว เสีย 5 ตัว และสร้างทดแทน 5 ตัว: ก่อน QC ยังพร้อม 0; เมื่อชุดเดิมผ่าน QC พร้อม 95; เมื่อชุดทดแทนผ่าน QC จึงพร้อมครบ 100 ไม่ใช่ 105

รายงานพร้อมส่งเป็นยอดรวมทั้งออเดอร์ฉบับปัจจุบัน แม้เปิดอ่านประวัติ PS ฉบับเก่าอยู่ ไม่ใช่ยอดเฉพาะใบที่กำลังเปิด

## ประวัติและข้อจำกัดของรอบนี้

- เก็บผู้แจ้ง ผู้ปิดปัญหา วันเวลา เหตุผล จำนวน และสายเชื่อมงานทดแทนไว้
- อินเทอร์เน็ตขาดหลังส่ง ให้ใช้ Retry คำขอเดิม ระบบไม่ตัดของเสียหรือสร้างร่างซ้ำ
- แก้ PS ฉบับใหม่ไม่ล้างปัญหาและของเสียที่เคยยืนยันในใบนั้น ไม่สามารถออกฉบับใหม่เพื่อหลบ Stop หรือทำให้ยอดกลับมาเพิ่มเอง
- ถ้ามีรายงานจำนวนค้าง ต้องให้เจ้าของ/แอดมินตรวจให้เสร็จก่อนลดจำนวนใน PS จนเหลือน้อยกว่าจำนวนที่ต้องตรวจ เพื่อให้ยังบันทึกของเสียจริงจากงานเดิมได้
- เมื่อออเดอร์เปลี่ยนฉบับ ยังปิดบันทึกปัญหาเก่าได้ แต่ไม่สร้างงานทดแทนจากคำสั่งของออเดอร์เก่า ต้องตรวจและจัดงานกับออเดอร์ฉบับปัจจุบัน
- หลังปิดปัญหา เจ้าของ/ADMIN แก้จำนวนได้ผ่านปุ่มใหม่ ต้องตรวจชิ้นงานและเหตุผล เก็บประวัติเดิม ไม่ใช่ปุ่มลบการยืนยันเก่า
- นำงานเดิมข้ามฉบับได้ผ่านการทบทวนและรอกราฟิกอนุมัติตามคู่มือใช้ต่อ ไม่ทำอัตโนมัติ
- รับเงิน คืนเงิน และส่งสินค้าอยู่ในส่วนแยกตามคู่มือรับเงิน/ส่งสินค้า การแก้จำนวนปัญหาไม่เปลี่ยนรายการเงินจริง

## ผลตรวจรอบนี้

ชุดทดสอบระบบรวม 41 กรณีผ่าน และตรวจซ้ำส่วนงานผลิต/ข้อยกเว้นฉบับล่าสุดอีก 4 กรณีหลังเพิ่มการรักษาจำนวนในรายงานที่ยังค้าง ตรวจทั้งสิทธิ์แอดมิน/พนักงาน Stop ที่ไม่กระทบขั้นก่อนหน้า Continue ที่ยังทำงานได้ การห้ามยอดเกินออเดอร์ ทดแทนเสียซ้ำ รายงานซ้ำ การปิดปัญหาพร้อมกัน การปล่อยจำนวนที่ยังไม่ได้ทำ และของเสียที่ยังอยู่ในประวัติเมื่อยกเลิก PS

ทดสอบผ่านเบราว์เซอร์จริง: รายงานเสียหนึ่งตัวและ Stop เลเซอร์ → ยืนยันของเสียและสร้างร่างทดแทน → จำลองการเชื่อมต่อขาดแล้วลองคำขอเดิมโดยไม่สร้างซ้ำ → เตรียมไฟล์ทดแทน → ผ่านงานผลิตทั้งหกขั้นและ QC → จำนวนพร้อมส่งเพิ่มจาก 4 เป็น 5 จากออเดอร์ 12 ตัว โดยไม่มีออเดอร์/ใบแจ้งหนี้เพิ่ม และยังแสดงว่าเป็นเพียงบางส่วน

ตรวจหน้าจอมือถือ 320/390 พิกเซลไม่ล้น พนักงานไม่มีปุ่มปิดปัญหา ยอดเงินไม่ถูกเปิดให้ฝ่ายผลิต ตรวจคุณภาพโค้ดและการสร้างโปรแกรมผ่าน ฟอนต์ลาว/ไทยรวมในโปรแกรม และแยกโหลดหน้าพิมพ์เพื่อลดขนาดหน้าจอเริ่มต้น

ภาพตัวอย่างจากข้อมูลทดสอบอยู่ใน `test-results/production-issues-mobile.png` และ `test-results/production-exceptions-readiness.png` ใช้ฐานทดสอบแยกทั้งหมด ไม่แก้ข้อมูลจริง ยังไม่ได้ตรวจการผลิตหน้าร้านหรือฐานข้อมูลภายนอกที่ใช้งานพร้อมกันหลายเครื่อง
