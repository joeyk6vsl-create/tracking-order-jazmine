# ยกเลิกแผนนำงานผลิตเดิมมาใช้ต่อทั้งชุด

ใช้เมื่อเจ้าของหรือแอดมินยืนยันแผนใช้ต่องานผลิตผิด และต้องการกลับมาตรวจจำนวนใหม่ ระบบตรวจทุกใบในแผนก่อน แล้วปิดใบที่สร้างจากแผนนั้นและคืนสถานะใบเก่าพร้อมกัน ไม่ลบใบ ไม่ลบไฟล์ และไม่ลบประวัติ

## ใครใช้ได้ และเปิดตรงไหน

**เจ้าของ ADMIN_PROMAX และพนักงานแผนก ADMIN** ใช้ได้ กราฟิกยังตรวจและอนุมัติใบผลิตตามหน้าที่เดิม แต่ยกเลิกแผนใช้ต่อทั้งชุดไม่ได้ พนักงานฝ่ายผลิตไม่มีสิทธิ์ส่วนนี้

1. หยุดโปรแกรมด้วย Ctrl+C แล้วเปิด `START_JAZMINE.cmd` ใหม่ รีเฟรชเว็บ ไม่ต้องล้างข้อมูล
2. เปิด **เตรียมใบผลิต** แล้วเลือกออเดอร์
3. ใน **Review previous production** เปิดประวัติแผนที่ต้องการ แล้วกด **Check plan reversal**
4. อ่าน **Reversal effects** ว่าใบไหนจะถูกคืน และใบไหนจะถูกปิด รวมทั้งเหตุผลที่ระบบยังไม่อนุญาตถ้ามี
5. ตรวจงานที่หน้างานจริงด้วย หากยังไม่มีงานหรือการส่งเพิ่ม ให้ใส่เหตุผลและติ๊กยืนยันว่าตรวจทุกใบแล้ว
6. กด **Reverse entire reuse plan** ระบบบันทึกทั้งชุด ถ้าตรวจไม่ผ่านแม้ใบเดียว จะไม่ย้อนบางใบให้ก่อน
7. ถ้าการเชื่อมต่อขาดหลังส่งคำสั่ง ให้กด **Retry plan reversal** เพื่อตรวจคำขอเดิม ไม่ต้องเริ่มคำสั่งใหม่

หลังสำเร็จ ประวัติแสดง **Plan reversed** พร้อมผู้ทำ เวลา และเหตุผล แผนเดิมยังเปิดดูได้

## หลังยกเลิกแผน ต้องทำอะไรต่อ

ใบเก่ากลับไปเป็นสถานะก่อนยืนยันแผนนั้น เช่น พร้อมใช้หรือกำลังแก้ร่าง แต่ยังเป็นใบของออเดอร์ฉบับเก่า ไม่ได้กลายเป็นคำสั่งผลิตฉบับล่าสุดโดยอัตโนมัติ

ให้เจ้าของหรือ ADMIN เลือกจำนวนใช้ต่อใหม่ใน **Review previous production** แล้วให้กราฟิกหรือเจ้าของตรวจใบใหม่ตามขั้นตอนเดิม ก่อนฝ่ายผลิตทำต่อ ใบที่ถูกปิดจากแผนผิดยังอยู่ในประวัติ ใบใหม่ที่อนุมัติภายหลังใช้เลขตามขั้นตอนออกใบตามปกติ ไม่ดึงเลขของใบที่ปิดกลับมาใช้ซ้ำ

ตัวอย่าง: งานเดิมมี 11 ตัว ส่งไปแล้ว 3 ตัว เหลือใช้ต่อได้ 8 ตัว ถ้าย้อนแผนแล้วเลือกใหม่ ระบบยังเหลือใช้ต่อ 8 ตัว ไม่เอา 3 ตัวที่ส่งแล้วกลับมาเพิ่ม พร้อมส่งของออเดอร์ล่าสุดจะไม่นับใบที่ปิดจากแผนผิด ระหว่างรอแผนและการอนุมัติใหม่

## กรณีที่ย้อนอัตโนมัติได้

- แผนใหม่ที่ยืนยันหลังเพิ่มส่วนนี้ ระบบมีข้อมูลสถานะใบเก่าก่อนปิดครบ
- ออเดอร์ยังใช้งานอยู่และยังเป็นฉบับเดียวกับตอนยืนยันแผน
- ข้อมูลใบเก่าที่ปิดไว้ยังตรงกับตอนยืนยันแผน
- ใบใหม่ยังเป็นร่าง หรืออนุมัติครั้งแรกแล้วโดยมีเพียงสถานะงานเดิมที่รับมา ยังไม่มีการทำงานเพิ่มตามใบใหม่
- ถ้าเผลอปิดใบปลายทางไปแล้ว แต่ยังไม่มีงาน ปัญหา หรือส่งต่อจากใบนั้น ก็ตรวจย้อนทั้งแผนเพื่อปล่อยจำนวนที่จองไว้ได้ การปิดใบเดี่ยวอย่างเดียวไม่ได้แปลว่าแผนถูกย้อนแล้ว
- ไม่มีรายการเตรียมส่งค้าง และไม่มีประวัติงาน ปัญหา ส่งสินค้า หรือแผนใช้ต่อถัดไปที่ผูกกับใบใหม่

แผนที่เลือกไม่ใช้ต่อเลยก็ย้อนคืนใบเก่าได้ตามเงื่อนไขเดียวกัน ระบบคืนร่างเป็นร่าง ไม่เดาให้เป็นใบพร้อมผลิต

## ถ้าระบบไม่ให้ย้อน

| เหตุผล | ควรทำอย่างไร |
|---|---|
| มีรายการเตรียมส่งค้าง | ตรวจและจัดการรายการเตรียมส่งก่อน แล้วกดตรวจใหม่ |
| มีงานเพิ่ม ปัญหา หรือประวัติส่งจากใบใหม่ | ให้เจ้าของ/ADMIN ตรวจงานที่เกิดจริง แล้วแก้ผ่านขั้นงานผลิต ปัญหา หรือส่งสินค้าเดิม ระบบไม่ลบกิจกรรมเหล่านั้นเพื่อย้อนแผน |
| ใบใหม่ถูกแก้เป็นฉบับถัดไป หรือมีแผนใช้ต่ออีกทอด | ตรวจสายงานทั้งชุดก่อน ไม่ย้อนทับคำสั่งที่มีงานต่อเนื่องแล้ว |
| ข้อมูลใบเก่าเปลี่ยน เช่น แก้จำนวนปัญหาหรือรายการส่ง | ตรวจข้อมูลปัจจุบันและวางแผนจัดการตามงานจริง |
| ออเดอร์มีฉบับใหม่ ยกเลิกแล้ว หรือเก็บข้อมูลเก่าแล้ว | ใช้สถานะปัจจุบันและขั้นจัดการออเดอร์เดิมก่อน ไม่ย้อนออเดอร์ด้วยปุ่มนี้ |
| แผนเก่าก่อนเพิ่มส่วนนี้ | ระบบไม่มีหลักฐานสถานะก่อนปิดครบ จึงให้ตรวจด้วยคน ไม่เดาสถานะย้อนหลัง |
| ข้อมูลเปลี่ยนหลังเปิดหน้าตรวจ | กด **Check reversal again** แล้วตรวจผลใหม่ก่อนยืนยัน |

การยกเลิกการส่งหรือปิดปัญหาภายหลังไม่ได้ลบประวัติที่เคยเกิด ระบบจึงยังอาจปฏิเสธการย้อนอัตโนมัติได้ ไม่มีปุ่มข้ามเงื่อนไขเหล่านี้

## สิ่งที่ต้องดูประกอบ

การย้อนแผนไม่แก้ราคา ไม่คืนเงิน ไม่ยกเลิกรับเงิน และไม่ย้อนการส่งสินค้า เงินค้างยังคิดจากราคาออเดอร์ล่าสุดกับรายการเงินจริงตามเดิม หากต้องแก้เงินให้ใช้เมนูรับเงิน/คืนเงินตามสิทธิ์เดิม

ใบผลิตฉบับที่เคยออกและ PDF ต้นฉบับยังอยู่ ไฟล์เดิมไม่ถูกเขียนทับเป็นเนื้อหาใหม่ ต้องดูสถานะใบปัจจุบันประกอบก่อนนำกระดาษเก่าไปใช้ การคืนสถานะไม่ได้คืนวัตถุดิบหรือบันทึกต้นทุนให้อัตโนมัติ

ข้อมูลแผน การย้อน เหตุผล และสายงานเดิมรวมอยู่ในการสำรองและกู้คืน การเปลี่ยนบัญชีหรือสิทธิ์มีผลกับการยืนยันและการลองคำขอเดิมด้วย

## ไฟล์ที่เกี่ยวข้อง — อธิบายภาษาไทย

ชุดตรวจรวมผ่าน 128 กรณี และชุดตรวจเฉพาะส่วนรุ่นสุดท้าย 10 กลุ่มผ่าน โดยบางกรณีซ้ำกัน จึงไม่บวกจำนวนสองชุดเป็นยอดรวม ตรวจคุณภาพโค้ดและสร้างเว็บผ่านแล้ว

ผลตรวจ 2 พฤศจิกายน 2026: ชุดตรวจเฉพาะการย้อนแผนผ่าน 10 กลุ่ม ครอบคลุมหลายใบพร้อมกัน การลองคำขอเดิม สิทธิ์ บัญชีเปลี่ยน ข้อมูลเก่า/เปลี่ยนฉบับ ร่างและใบพร้อมที่ปิดผิด งาน/ปัญหา/รายการส่งต่อ เงินมัดจำ ส่งบางส่วน และกู้ข้อมูลเป็นสำเนาแยก ทดลองหน้าเว็บจริง ADMIN → ย้อนแผน → เลือกใหม่ → GRAPHIC อนุมัติ → บันทึกงานเพิ่มแล้วบล็อกการย้อน พร้อมตรวจมือถือ 320/390px และภาพทุกแบบแล้ว เส้นทางเดิมใช้ต่องาน แก้ปัญหา และยกเลิกออเดอร์ผ่านร่วมด้วย ข้อมูลทั้งหมดเป็นข้อมูลทดสอบ ไม่ใช่ออเดอร์หรือรายการเงินจริงของร้าน
