# ผลตรวจข้อมูลจำนวนมากและการทำงานพร้อมกัน — W10

## สิ่งที่ทำในรอบนี้

ตรวจระบบด้วยข้อมูลสมมติแยกจากร้าน และปรับให้รายงานอ่านข้อมูลชุดเดียวร่วมกัน แทนการคำนวณยอดเดิมซ้ำหลายรอบ สูตรเงิน สิทธิ์ของเจ้าของ และวิธีใช้งานหน้าจอยังใช้กติกาเดิม

ชุดตรวจมีลูกค้า 20,000 ราย ออเดอร์ 10,001 รายการ ประวัติออเดอร์ 20,001 ฉบับ รายการเงิน 30,000 รายการ ใบผลิต 2,001 ใบ และเพิ่มประวัติการทำงานอีก 100,000 รายการ ไม่ได้เพิ่มข้อมูลเหล่านี้เข้าร้าน

## ความเร็วที่วัดได้

วัดผ่านการขอข้อมูลจากโปรแกรมที่เปิดเฉพาะเครื่อง ใช้เครื่อง i5-13420H หน่วยความจำ 32 GB แต่ละงานเตรียมหนึ่งรอบแล้ววัดอีก 7 รอบ ตัวเลขด้านล่างเป็นค่ากลางของรอบวัด ไม่ใช่เวลารวมวาดหน้าจอหรือความเร็วผ่านอินเทอร์เน็ต

| งาน                                   |         ก่อนปรับ |         หลังปรับ |
| ------------------------------------- | ---------------: | ---------------: |
| หน้าลูกค้า 25 ราย                     |     0.010 วินาที |     0.005 วินาที |
| ค้นหาออเดอร์                          |     0.140 วินาที |     0.131 วินาที |
| คิวงานผลิต 50 ใบ                      |     0.077 วินาที |     0.086 วินาที |
| รายชื่อออเดอร์ในหน้ารับเงิน 50 รายการ |     0.117 วินาที |     0.126 วินาที |
| เปิดรายละเอียดรับเงินหนึ่งออเดอร์     |     0.022 วินาที |     0.030 วินาที |
| รายงานย้อนหลัง 180 วัน                | **1.539 วินาที** | **0.677 วินาที** |

การปรับมุ่งที่รายงาน ส่วนงานอื่นไม่ได้แก้ ความต่างเล็กน้อยของงานอื่นเกิดจากการวัดคนละรอบ รายงานใช้เวลาลดลงประมาณ 56% ในชุดนี้ เมื่อส่งคำขออ่านพร้อมกัน 12 คำขอ แบ่งเป็นรายงาน 4 ค้นหา 4 และคิวผลิต 4 ใช้เวลาจนครบทั้งหมดจาก 7.062 เหลือ 3.797 วินาที

ตรวจว่ายอดขาย เงินสุทธิ ยอดค้าง จำนวนออเดอร์ และการแบ่งหน้าตรงกับข้อมูลสมมติที่ทราบคำตอบไว้แล้ว พร้อมจำกัดข้อมูลที่ส่งกลับตามขนาดหน้าที่ใช้อยู่ ไม่ส่งออเดอร์ทั้งหมื่นรายการกลับมาวาดพร้อมกัน

ไฟล์ผลวัดต้นทางอยู่ใน `test-results/local-load-baseline.json` และ `test-results/local-load-optimized.json` รอบตรวจล่าสุดพร้อมหน้าจออยู่ใน `test-results/local-load-latest.json` ไฟล์เหล่านี้เป็นผลทดสอบในเครื่องและไม่เก็บในประวัติการพัฒนา

## เมื่อต่างคนกดพร้อมกัน ระบบทำอย่างไร

ทดลองผ่านการเข้าสู่ระบบอิสระ 12 ชุดของบัญชีเจ้าของและ ADMIN รวม 2 บัญชี และตรวจการบันทึกต่างออเดอร์อีก 12 รายการ ไม่ได้จำลองเป็นพนักงาน 12 บัญชีที่ใช้คนละอุปกรณ์จริง

| เหตุการณ์ที่ตรวจ                               | ผลที่ต้องได้และตรวจผ่าน                                                 |
| ---------------------------------------------- | ----------------------------------------------------------------------- |
| ส่งคำขอรับเงินเดิมซ้ำ 12 ครั้ง                 | ได้รายการรับเงินเดียว ยอดและประวัติไม่เพิ่มซ้ำ                          |
| หลายหน้าจอรับเงินคนละคำขอบนออเดอร์ฉบับเดียวกัน | สำเร็จหนึ่งคำขอ ที่เหลือต้องเปิดยอดล่าสุดก่อนทำต่อ                      |
| เจ้าของคืนเงินแข่งกันจากใบรับเงินเดียว         | ไม่คืนเกินต้นทาง และ ADMIN ยังคืนเงินไม่ได้                             |
| กดเริ่มผลิตพร้อมกันหลายครั้ง                   | มีการเริ่มงานและประวัติหนึ่งครั้ง                                       |
| เตรียมส่งสินค้าจากจำนวนที่เหลือก้อนเดียวกัน    | ไม่จองเกินออเดอร์ ยืนยันส่งซ้ำไม่หักสินค้าที่ผ่าน QC ซ้ำ                |
| เปิดรายงานระหว่างมีคนรับเงิน                   | ตัวเลขรวมกับรายละเอียดตรงกัน ใช้ข้อมูลที่บันทึกสำเร็จแล้วชุดเดียว       |
| หลายคนแก้ร่างจากฉบับเดิม                       | เก็บการแก้ครบชุดของผู้ที่บันทึกสำเร็จหนึ่งคน ไม่ผสมหรือทับข้อมูลเงียบ ๆ |
| รับเงิน 12 ออเดอร์ต่างกันพร้อมกัน              | สำเร็จครบและเลขใบรับเงินไม่ซ้ำ                                          |

หากพบข้อความว่าข้อมูลเปลี่ยนแล้ว ให้เปิดข้อมูลล่าสุด ตรวจว่าอีกคนทำรายการเดียวกันไปแล้วหรือเป็นคนละรายการ จากนั้นจึงบันทึกใหม่ตามที่จำเป็น ไม่กดสร้างรายการใหม่เพื่อข้ามคำเตือนทันที

ตรวจเพิ่มเรื่องยอดเงินรวมที่มีตัวเลขยาวมาก การใช้ราคาออเดอร์ฉบับล่าสุด รายงานครบทุกหน้า และช่วงวันที่ไม่มีข้อมูล เพื่อให้ความเร็วที่เพิ่มไม่แลกกับยอดคลาดเคลื่อน

ผลตรวจสุดท้าย: ชุดรวมผ่าน **68 กรณี** รวมงานเดิมและงานที่เพิ่มรอบนี้ ตรวจสร้างโปรแกรม ความถูกต้องและรูปแบบไฟล์ผ่าน เส้นทางหน้าติดตาม/รายงาน/ค้นหาเดิมผ่านเบราว์เซอร์ และหน้าจอข้อมูลมากผ่านการตรวจยอด การเปลี่ยนหน้ารายงานกับผลค้นหา และมือถือ 320/390px ไม่พบข้อผิดพลาดหน้าจอในชุดที่ตรวจ

## ขอบเขตที่ผ่านกับสิ่งที่ต้องตรวจต่อ

รอบนี้ใช้ฐานข้อมูลทดสอบในหน่วยความจำและส่งคำขอพร้อมกันเข้าโปรแกรมในเครื่อง ฐานรุ่นนี้จัดคิวการบันทึกผ่านการเชื่อมต่อเดียว ผลนี้ยังไม่รับรองความเร็วเมื่ออ่านดิสก์จริง เครือข่ายร้าน อินเทอร์เน็ต หรือฐาน PostgreSQL ภายนอกที่มีหลายการเชื่อมต่อ

ข้อมูลจำนวนมากสร้างขึ้นสำหรับตรวจการอ่าน ส่วนกรณีรับเงิน/ส่งสินค้า/ผลิต/แก้ร่างส่งผ่านขั้นตอนบันทึกของระบบจริงในฐานทดสอบ มีการตรวจหน้าจอชุดใหญ่ผ่านเบราว์เซอร์แยกด้วย ไม่ใช้ข้อมูลจำลองเป็นหลักฐานว่าออเดอร์ทุกใบพร้อมผลิตจริงหรือไฟล์สำรองขนาดใหญ่ผ่านการกู้คืนแล้ว

W10 ยังเหลือการทดลองกับเจ้าของและแต่ละแผนกบนอุปกรณ์จริง การตรวจฐานภายนอกและเครือข่ายตามสถานที่ติดตั้ง สำรองอัตโนมัตินอกเครื่อง และแผนเริ่มใช้/ย้อนกลับ ส่วนงานค้างจาก W4–W9 และข้อมูลต้นทุนจริงยังอยู่ในแผน

งานถัดไปให้ทบทวนกรณีแก้ออเดอร์หลังเริ่มผลิตและการนำงานเดิมไปใช้กับออเดอร์ฉบับใหม่ ก่อนจัดรอบทดลองงานจริงรายแผนก ตามลำดับ W10 ที่ตกลงไว้

เรียก `pnpm test` เพื่อตรวจการทำงานรวม เรียก `pnpm test:load` เพื่อสร้างฐานจำลองใหม่ วัดเวลา และตรวจหน้าจอข้อมูลมาก ต้องมี Edge หรือ Chromium สำหรับทดสอบ หน้าจอชุดนี้ใช้ช่อง 5182 ชั่วคราว ส่วนหลังบ้านเลือกช่องว่างเอง เมื่อจบจะปิดโปรแกรมทดสอบและทิ้งฐานในหน่วยความจำ ไม่มีการลบหรือเปลี่ยนฐานร้าน

รายละเอียดวิธีลดการคำนวณซ้ำสำหรับผู้พัฒนาอ้างอิง [เอกสาร PostgreSQL เรื่องการใช้ผลคำนวณร่วมกัน](https://www.postgresql.org/docs/current/queries-with.html#QUERIES-WITH-CTE-MATERIALIZATION) ไม่เพิ่มที่เก็บยอดค้างอีกชุด จึงไม่ต้องคอยทำให้ยอดที่เก็บซ้ำตรงกับรายการเงินจริง
