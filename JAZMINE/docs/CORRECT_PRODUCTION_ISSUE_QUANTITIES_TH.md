# แก้จำนวนปัญหาการผลิตที่ปิดไปแล้ว

ใช้เมื่อยืนยันปัญหาไปแล้ว แต่กลับมาตรวจพบว่าบันทึกจำนวนผิด เช่น เดิมบันทึกเสีย 3 ตัว แต่เสียจริง 2 ตัว อีก 1 ตัวยังใช้ได้ เจ้าของและพนักงานแผนก ADMIN แก้ได้ พร้อมระบุเหตุผลทุกครั้ง ระบบเก็บรายงานแรกและการยืนยันครั้งก่อนทั้งหมดไว้

## วิธีลองใช้

1. ถ้ายังเปิดโปรแกรมรุ่นก่อนอยู่ ให้หยุดด้วย Ctrl+C แล้วเปิด `START_JAZMINE.cmd` ใหม่ จากนั้นรีเฟรชหน้าเว็บ ระบบเพิ่มส่วนเก็บประวัติให้เอง ไม่ต้องล้างข้อมูลหรือตั้งบัญชีเจ้าของใหม่
2. เปิดคิวงานผลิต แล้วเปิดใบผลิตต้นทางที่มีปัญหา
3. ในหัวข้อ **Production issues** เลือกปัญหาที่เป็น **Resolved** แล้วกด **Correct recorded quantities**
4. เทียบจำนวนก่อนแก้กับชิ้นงานจริง กรอกจำนวนใหม่ในแต่ละไซซ์ ถ้ามีร่างงานทดแทนที่ยังไม่เคยออกใบ สามารถปรับจำนวนร่างนั้นพร้อมกันได้ ใส่ศูนย์ทุกรายการของร่างนั้นเพื่อยกเลิกร่าง
5. ติ๊กยืนยันว่าได้ตรวจชิ้นงาน งานทดแทน และจำนวนที่ส่งหรือใช้ต่อแล้ว ใส่เหตุผล แล้วกด **Save quantity correction**
6. ตรวจจำนวนปัจจุบัน และเปิด **Resolution & correction history** เพื่อดูผู้แก้ เวลา เหตุผล และตัวเลขแต่ละรอบ หากการเชื่อมต่อขาด ให้กด **Retry quantity correction** ในฟอร์มเดิม เพื่อให้ระบบตรวจคำขอเดิมก่อน

ถ้ามีคนอื่นเปลี่ยนข้อมูลระหว่างกรอก ระบบจะไม่รับข้อมูลเก่าทับ ให้เปิดข้อมูลล่าสุดด้วย **Reload correction** แล้วตรวจอีกครั้ง

## แต่ละช่องหมายถึงอะไร

| ช่อง                  | ความหมาย                                                                                                  |
| --------------------- | --------------------------------------------------------------------------------------------------------- |
| Usable                | จำนวนที่ตรวจแล้วใช้ได้ ไม่ใช่การเพิ่มสินค้านอกออเดอร์                                                     |
| Scrap                 | จำนวนที่เสียและไม่ใช้ส่งจากใบนี้ หักออกจากจำนวนสุทธิ                                                      |
| Release               | จำนวนที่ยังไม่ได้ทำและปล่อยออกจากใบนี้เพื่อจัดใหม่ หักออกจากจำนวนสุทธิ                                    |
| Dismiss               | จำนวนที่รายงานซ้ำหรือไม่ควรนับเป็นปัญหา ไม่หักสินค้าเพิ่ม                                                 |
| Net in sheet          | จำนวนสุทธิของใบหลังหักเสียและปล่อยคืน รวมสินค้าที่ส่งหรือใช้ต่อไปแล้ว จึงไม่ใช่ยอดพร้อมส่งที่เหลือทั้งหมด |
| Committed replacement | จำนวนที่ผูกกับงานทดแทนอยู่ก่อนแก้ ต้องตรวจร่างหรืองานนั้นร่วมด้วย                                         |

ยอดตรวจใหม่ไม่จำเป็นต้องเท่าจำนวนรายงานแรก เพราะรายงานแรกอาจผิดด้วย ถ้าใส่ผิดไซซ์ ให้แก้ตัวเลขในไซซ์ที่ถูกต้องได้เฉพาะรายการที่อยู่ในใบผลิตต้นทางนั้น ส่วนจำนวนรายงานแรกยังอยู่ในประวัติ

## ตัวอย่าง

ใบผลิต 11 ตัว ผ่านตรวจคุณภาพแล้ว เดิมบันทึกเสีย 3 ตัว เหลือพร้อมส่ง 8 ตัว และสร้างร่างทดแทนไว้ 3 ตัว ต่อมาตรวจพบว่าเสียจริง 2 ตัว ใช้ได้อีก 1 ตัว:

- เปลี่ยน Scrap เป็น 2 และ Usable เป็น 1
- ถ้าร่างทดแทนยังไม่เคยออกใบ ให้ลดจาก 3 เป็น 2 ในฟอร์มเดียวกัน
- บันทึกเหตุผล เช่น “ตรวจชิ้นงานจริง พบเสีย 2 ตัว อีก 1 ตัวใช้ได้”

หลังบันทึก ใบต้นทางเหลือพร้อมส่ง 9 ตัว ร่างทดแทนเป็น 2 ตัว ร่างนี้ยังต้องให้กราฟิกตรวจอนุมัติและผลิตจนผ่านตรวจคุณภาพก่อนนับพร้อมส่ง รายงานแรกที่แจ้ง 3 ตัวและการยืนยันเสีย 3 ตัวครั้งแรกยังเปิดดูได้

## กรณีที่ต้องตรวจงานที่เกี่ยวข้องก่อน

- ลดจำนวนสุทธิให้ต่ำกว่าที่ส่งแล้วหรือใช้ผลิตต่อในใบใหม่แล้วไม่ได้ ต้องตรวจรายการส่งหรือแผนใช้ต่อก่อน ไม่ลบข้อเท็จจริงที่เกิดขึ้นแล้ว
- ถ้าเสียจริงน้อยลง แต่งานทดแทนยังผูกจำนวนเดิมอยู่ ระบบจะให้ตรวจงานทดแทนก่อน ร่างที่ยังไม่เคยออกใบปรับในฟอร์มนี้ได้ ส่วนที่เคยออกใบ เริ่มผลิต ส่ง หรือใช้ต่อแล้ว ต้องตรวจแยก ฟอร์มนี้ไม่ยกเลิกหรือเปลี่ยนงานเหล่านั้นให้เอง
- แม้งานทดแทนถูกปิดใบไปแล้ว จำนวนที่ส่งหรือใช้ต่อยังถือว่าผูกไว้ ไม่คืนสิทธิ์ผลิตทดแทนส่วนนั้นให้ซ้ำ
- ถ้าใบอื่นรับจำนวนที่ขาดไปแล้ว การแก้ให้ใบเดิมมีจำนวนมากขึ้นต้องไม่ทำให้รวมเกินออเดอร์ ต้องตรวจการแบ่งงานใบอื่นก่อน
- หากแก้ใบเก่าที่ปิดหลังเปลี่ยนออเดอร์ ชิ้นงานที่กลับมาใช้ได้จะไม่เพิ่มเข้าใบใหม่อัตโนมัติ ต้องตรวจการจัดงานต่อ แผนใช้ต่อที่ยังมีผลยังจองจำนวนไว้แม้ร่างปลายทางถูกปิด เพิ่มการ [ตรวจและย้อนแผนทั้งชุด](REVERSE_PRODUCTION_REUSE_PLAN_TH.md) แล้วเมื่อผ่านเงื่อนไข หากข้อมูลต้นทางเปลี่ยนจากตอนยืนยันแผน ต้องตรวจด้วยคน ไม่ย้อนทับจำนวนที่แก้ใหม่
- ใบต้นทางที่ยังไม่ผ่านตรวจคุณภาพ หรือมีปัญหาอื่นค้าง จะยังไม่เพิ่มยอดพร้อมส่งเพียงเพราะแก้ตัวเลข

การแก้นี้แก้บันทึกจำนวน ไม่เปลี่ยนราคา เงินรับ คืนเงิน รายการส่งจริง หรือใบผลิตที่เคยออกไปแล้ว และยังไม่ตัดคลังวัตถุดิบหรือคิดต้นทุนให้เอง การเพิ่มงานทดแทนใช้ปุ่มเดิมโดยคิดจากยอดล่าสุด ไม่มีการสร้างร่างเพิ่มอัตโนมัติจากการแก้
