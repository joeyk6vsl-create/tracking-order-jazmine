# รายการที่เป็นของแถมล้วน

เพิ่มสินค้าเป็นของแถมคนละไซซ์หรือคนละรายการกับสินค้าที่ซื้อได้ โดยใส่ **จำนวนซื้อ 0** และ **จำนวนแถมมากกว่า 0** ระบบไม่บังคับให้เพิ่มจำนวนซื้อหลอก ๆ เพื่อให้บันทึกได้ ของแถมยังต้องผลิต ตรวจคุณภาพ และส่งให้ครบ

## วิธีใช้งาน

1. ปิดโปรแกรมที่เปิดอยู่ด้วย Ctrl+C แล้วเปิด `START_JAZMINE.cmd` ใหม่ จากนั้นรีเฟรชหน้าเว็บ ใช้บัญชีเจ้าของหรือแผนก ADMIN ตามเดิม
2. เปิด **ร่างออเดอร์** สร้างร่างใหม่หรือเปิดแก้ร่างที่มีอยู่
3. เพิ่มแบบเสื้อ ผ้า ส่วนประกอบ และไซซ์ผ่านส่วนเพิ่มรายการเดิม
4. ถ้ารายการนั้นเป็นของแถมทั้งหมด กด **Make gift-only** ระบบย้ายจำนวนซื้อเดิมไปช่องแถม โดยจำนวนสินค้ารวมยังเท่าเดิม หรือกรอกช่องจำนวนซื้อเป็น 0 และช่องแถมตามจริงด้วยตัวเอง
5. ถ้าต้องการกลับเป็นรายการคิดเงิน กด **Make paid** ระบบย้ายจำนวนแถมทั้งหมดกลับเป็นจำนวนซื้อ ตรวจยอดใหม่ก่อนบันทึก
6. เลือกกลุ่มราคา สกุลเงิน ส่วนลด และกติกาของแถมที่ยอดรวมร่าง ใส่เหตุผล กดตรวจยอด แล้วบันทึกตามเดิม

ในหน้า **ราคาและส่วนลด** และส่วนเพิ่มรายการ ก็ใส่จำนวนที่คิดเงิน 0 และจำนวนแถมได้ ถ้าทั้งจำนวนซื้อและแถมเป็น 0 ระบบจะให้ใส่จำนวนหรือนำรายการนั้นออก จำนวนแต่ละช่องยังจำกัดสูงสุด 10,000 ตัวต่อรายการ การเปลี่ยนด้วยปุ่มต้องไม่ทำให้ช่องปลายทางเกินขีดจำกัด หากเกินให้แบ่งรายการก่อน

## ตัวอย่างซื้อและแถมคนละไซซ์

| รายการ | จำนวนซื้อ | จำนวนแถม | ต้องผลิตและส่ง | ยอดเงินของรายการ                         |
| ------ | --------: | -------: | -------------: | ---------------------------------------- |
| ไซซ์ M |        10 |        0 |             10 | คิดตามราคาสินค้าที่ซื้อ                  |
| ไซซ์ L |         0 |        1 |              1 | 0 กีบเมื่อข้อมูลราคาครบ                  |
| รวม    |        10 |        1 |             11 | คิดเงินเฉพาะจำนวนซื้อ แล้วลดตามกติกาเดิม |

จะวางรายการแถมไว้ก่อนหรือหลังรายการซื้อก็ได้ ในใบแจ้งหนี้แถวของแถมจะแสดงซื้อ 0 แถมตามจริง และยอดรายการเป็น 0 การคิดส่วนลดทั้งเปอร์เซ็นต์และเงินยังทำที่ยอดรวมเพียงครั้งเดียว

ส่งไซซ์ M ครบ 10 ตัวอย่างเดียวยังไม่ถือว่าส่งออเดอร์ครบ ถ้ายังไม่ได้ส่งไซซ์ L ที่แถม 1 ตัวด้วย ของแถมต้องมีใบผลิต ไฟล์ที่กราฟิกอนุมัติ และผ่านตรวจคุณภาพตามกฎเดิมก่อนยืนยันส่ง ส่วนการเตรียมรายการส่งล่วงหน้ายังทำได้ตามขั้นส่งเดิม

## ซื้อครบแถมอัตโนมัติ

ใช้เฉพาะจำนวนซื้อคำนวณสิทธิ์แถม ของแถมไม่สร้างสิทธิ์แถมรอบใหม่ เช่น เจ้าของตั้งซื้อ 10 แถม 1 ซื้อ M 10 ตัวแล้วแถม L 1 ตัว สิทธิ์ยังเป็น 1 ไม่ใช่คิดจากจำนวนรวม 11

เมื่อเลือกอัตโนมัติ ต้องจัดจำนวนแถมลงรายการและไซซ์ให้รวมเท่ากับสิทธิ์ที่คำนวณได้ ถ้าเปลี่ยนจำนวนซื้อแล้วสิทธิ์เปลี่ยน ต้องตรวจจำนวนแถมใหม่ก่อนบันทึก ระบบไม่ตั้งกติกาซื้อ 10 แถม 1 ให้ร้านเอง ตัวเลขนี้เป็นตัวอย่าง

ปุ่ม **จัดของแถมทั้งหมดให้รายการแรก** จะไม่เปิดให้กดถ้าการย้ายจะทำให้รายการแถมล้วนอื่นกลายเป็นรายการว่าง ให้จัดผ่านช่องแถมแต่ละรายการ เพื่อรักษาไซซ์ที่ต้องส่งจริง หากต้องการแถมเองนอกสิทธิ์อัตโนมัติ ให้ปิดโหมดอัตโนมัติแล้วกรอกจำนวนเองตามกติกาเดิม

## ทั้งออเดอร์เป็นของแถม

ทำได้ในโหมดกำหนดแถมเอง โดยทุกรายการซื้อ 0 และมีจำนวนแถมจริง ยอดขายและยอดค้างเป็น 0 แต่ยังต้องตรวจไฟล์ ผลิต และส่งของแถมให้ครบ ไม่มีการสร้างรายการรับเงินให้เอง สถานะเงินที่ไม่ค้างไม่ได้แปลว่าร้านรับเงินจริงมาแล้ว

รายการแถมไม่ได้แปลว่าต้นทุนผลิตเป็นศูนย์ ระบบยังไม่คำนวณกำไรจนกว่าข้อมูลต้นทุนจะครบ และไม่ใส่ราคาที่ไม่ทราบเป็นศูนย์ให้เอง การเลือกสินค้า ผ้า ไซซ์ ส่วนประกอบ ราคา และอัตราแลกเปลี่ยนยังตรวจความพร้อมตามกฎเดิม

## ประวัติและสิทธิ์

เจ้าของและ ADMIN ใช้งานได้ตามสิทธิ์สร้าง/แก้ออเดอร์เดิม ต้องใส่เหตุผลเมื่อบันทึกแก้ร่าง การแก้ออเดอร์ที่ยืนยันแล้วต้องตรวจและยืนยันเป็นฉบับใหม่ ประวัติราคาและจำนวนฉบับก่อนยังอยู่ ไม่เปลี่ยนใบเก่าทับกัน และไม่ข้ามขั้นทบทวนงานผลิตหากมีงานเดิมอยู่

ถ้าการเชื่อมต่อขาดระหว่างบันทึกร่าง ให้ลองบันทึกร่างเดิมอีกครั้งก่อนเปลี่ยนข้อมูล ระบบยังใช้การตรวจคำขอเดิมของร่าง ไม่เพิ่มร่างซ้ำจากการลองเดิม

## ไฟล์และหน้าที่

ใช้ส่วนราคาและร่างเดิมร่วมกัน ไม่สร้างระบบของแถมแยกอีกชุด และไม่ต้องเพิ่มโครงสร้างฐานข้อมูลใหม่

| ไฟล์ในโฟลเดอร์ JAZMINE                          | เกี่ยวกับอะไร                                                                                                    |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `packages/contracts/src/pricing.ts`             | ยอมให้ซื้อ 0 แต่รายการสินค้าจริงต้องมีซื้อหรือแถมอย่างน้อยหนึ่งตัว                                               |
| `packages/contracts/src/orders.ts`              | แยกข้อมูลหัวร่างจากรายการจริง เพื่อวางของแถมเป็นรายการแรกได้ แต่ยังห้ามร่างว่าง                                  |
| `apps/web/src/features/orders/DraftEditor.tsx`  | ปุ่มเปลี่ยนเป็นแถมล้วน/คิดเงิน ช่องจำนวน และป้องกันการย้ายแถมจนรายการว่าง                                        |
| `apps/web/src/features/pricing/PricingPage.tsx` | เพิ่มรายการที่ซื้อ 0 และแถมตามจริงผ่านหน้าราคาเดิม                                                               |
| `apps/server/src/orders/price-draft.ts`         | ใช้สูตรเดิมคิดเงินเฉพาะซื้อ รวมแถมลงจำนวนผลิต และคิดส่วนลดที่ยอดรวม                                              |
| `packages/contracts/src/fulfillment.ts`         | ใช้จำนวนซื้อบวกแถมในขั้นแบ่งผลิตและส่งตามกฎเดียวกัน                                                              |
| `tests/integration/gift-only.test.ts`           | ตรวจรายการว่าง โปรโมชั่น ส่วนลด ข้อมูลราคาที่ยังไม่ครบ ยืนยัน ผลิต ตรวจคุณภาพ ส่งบางส่วน ยอดศูนย์ และข้อมูลสำเนา |
| `tests/e2e/gift-only.mjs`                       | ลองกดจริง เปลี่ยนรายการกลับไปมา ตรวจจำนวน บันทึกซ้ำ ยืนยันและตรวจใบแจ้งหนี้ รวมหน้าจอมือถือ                      |

## ผลตรวจการใช้งาน

ตรวจระบบรวมผ่าน 95 กรณี รวม 4 กลุ่มใหม่ใน `gift-only.test.ts` ตรวจรูปแบบและสร้างโปรแกรมผ่าน ไม่มีการเพิ่มข้อมูลทดสอบลงฐานของร้าน

ผ่านเบราว์เซอร์จากร่างที่มีของแถมเป็นรายการแรก → แปลงกลับเป็นคิดเงินและแปลงกลับเป็นแถม → ตรวจรายการว่างและปุ่มย้ายแถม → ซื้อครบแถมร่วมส่วนลด → บันทึกแล้วขาดการเชื่อมต่อและลองเดิมไม่เพิ่มร่าง → ยืนยันออเดอร์ → ใบแจ้งหนี้แสดงยอดแถม 0 ส่วนอนุมัติไฟล์ ผลิต ตรวจคุณภาพและส่ง ตรวจผ่านบริการของระบบด้วยข้อมูลชุดเดียวกัน และตรวจสถานะส่งที่แสดงกลับบนเว็บเมื่อส่งรวมของแถมครบแล้ว เส้นทางกดงานกราฟิก/ผลิต/เงิน/ส่งเดิมผ่านเบราว์เซอร์ตรวจร่วมอีกชุด

ตรวจหน้าจอ 320/390px และภาพใน `test-results/gift-only-line-desktop.png`, `gift-only-line-mobile.png`, `gift-only-invoice.png` ใช้ข้อมูลสมมติแยกจากร้านทั้งหมด การทดสอบในเครื่องยังต้องตามด้วยการทดลองกับผู้ใช้และอุปกรณ์จริงก่อนเปิดใช้เต็มรูปแบบ
