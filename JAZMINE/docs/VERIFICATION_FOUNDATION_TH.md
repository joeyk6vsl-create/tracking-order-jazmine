# ผลตรวจระบบพื้นฐาน JAZMINE รุ่น 0.1

## เรื่องที่ตรวจ

ผู้ใช้เปิดหน้าจอ → สร้างเจ้าของ → เข้าสู่ระบบ → เพิ่มพนักงาน → พนักงานเปลี่ยนรหัส → ระบบตรวจสิทธิ์จากฐานข้อมูล → แสดงหน้าหลักตามบัญชี

## ผลที่ยืนยันแล้ว

| ส่วน | ผล |
|---|---|
| ตรวจชนิดข้อมูล TypeScript | ผ่าน |
| ตรวจรูปแบบและกฎ React ด้วย ESLint | ผ่าน |
| สร้างโปรแกรมหน้าจอและหลังบ้าน | ผ่าน |
| หลังบ้านและฐานข้อมูล | ผ่าน 15 กรณี |
| เส้นทางผ่านเบราว์เซอร์จริง | ผ่าน |
| หน้าหลังบ้าน `/api/v1/health` | ตอบ 200 และ database ready |
| หน้าจอเว็บสำหรับทดลอง | ตอบ 200 |
| บันทึกลงดิสก์ ปิด แล้วเปิดข้อมูลใหม่ | ผ่าน |
| หน้าจอที่ 320 และ 390 พิกเซล | ไม่มีข้อมูลล้นแนวนอนในหน้าที่ตรวจ |

## สถานการณ์สำคัญที่ตรวจแล้ว

- สร้างเจ้าของครั้งแรกพร้อมกันสองคำขอ สำเร็จได้คนเดียว
- รหัสผ่านเก็บเป็น Argon2id; รายการผู้ใช้ไม่ส่งรหัสหรือ hash ออกหน้าจอ
- เก็บรหัสอ้างอิงการเข้าสู่ระบบเป็น hash ในฐานข้อมูล และใช้คุกกี้ HttpOnly
- ไม่เก็บรหัสเข้าสู่ระบบใน localStorage หรือ sessionStorage
- คำขอแก้ไขที่ขาด CSRF หรือมาจาก Origin ที่ไม่อนุญาตถูกปฏิเสธ
- ป้องกันชื่อผู้ใช้ซ้ำและข้อมูลแผนกที่ไม่มีในระบบ
- รหัสชั่วคราวยังไม่ให้สิทธิ์ทำงานจนกว่าจะเปลี่ยน
- แก้ข้อมูลฉบับเก่าถูกปฏิเสธแทนการเขียนทับ
- ย้ายแผนก ปิดบัญชี หรือรีเซ็ตรหัส ทำให้การเข้าสู่ระบบเดิมใช้ต่อไม่ได้
- พนักงาน ADMIN ไม่มีสิทธิ์คืนเงิน รายงานรวม หรือแก้อัตราแลกเปลี่ยนในตารางสิทธิ์กลาง
- เจ้าของคนสุดท้ายไม่ถูกปิด/ลดสิทธิ์ รวมถึงเมื่อสองคนทำพร้อมกัน
- งานเบื้องหลังบันทึกการรับเหตุการณ์พื้นฐานซ้ำได้โดยไม่เพิ่มรายการรับซ้ำ
- ประวัติการเปลี่ยนแปลงไม่เก็บรหัสผ่าน

## ขอบเขตของผลตรวจ

ฐานที่ทดสอบจริงคือ PGlite ในเครื่อง เส้นทางตัวเชื่อม PostgreSQL ภายนอกสร้างไว้แต่ยังไม่ยืนยันกับบริการภายนอก ไม่มีผลทดสอบระบบออเดอร์ เงิน PDF การสำรองคืน หรือโหลดจำนวนมาก เพราะส่วนนั้นยังไม่ได้สร้าง

งาน worker รอบนี้รับเหตุการณ์พื้นฐานผู้ใช้และเก็บใบรับภายในเท่านั้น ยังไม่ได้เตรียม PDF หรือส่งการแจ้งเตือนให้ผู้ใช้จริง

สภาพแวดล้อมจำกัดสิทธิ์รอบแรกทำให้ทดสอบเปิดฐานลงดิสก์ไม่ได้ เมื่อตรวจซ้ำด้วยสิทธิ์เปิดไฟล์และโปรแกรมตามปกติผ่านครบ 15 กรณี การตรวจนี้ไม่ใช่การรับรองความปลอดภัยก่อนเปิดใช้งานสาธารณะ
