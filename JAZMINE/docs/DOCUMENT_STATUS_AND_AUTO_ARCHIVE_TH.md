# สถานะเอกสารและการเก็บออเดอร์เก่าอัตโนมัติ

เพิ่มสำเนา PDF ที่แสดงสถานะ ณ เวลาดาวน์โหลด และหน้าตั้งค่าการเก็บออเดอร์เก่าอัตโนมัติสำหรับเจ้าของ ข้อมูลเดิม เอกสารแต่ละฉบับ และประวัติยังอยู่ครบ

## เริ่มใช้งาน

หยุดโปรแกรมด้วย Ctrl+C แล้วเปิด `START_JAZMINE.cmd` ใหม่ รีเฟรชหน้าเว็บ ไม่ต้องล้างข้อมูลหรือตั้งบัญชีใหม่

### ดูหรือพิมพ์เอกสาร

เปิดใบเสนอราคา ใบแจ้งหนี้ ใบรับเงิน หรือใบผลิตตามขั้นตอนเดิม ส่วน **Stored original PDF** มีสองทางเลือก:

| ปุ่ม | ได้อะไร |
|---|---|
| Download stored PDF | ต้นฉบับที่ระบบเก็บไว้ตั้งแต่ออกใบ เหมาะกับการดูประวัติ |
| Download current-status copy | สำเนาจากต้นฉบับ พร้อมข้อความสถานะและเวลาที่ตรวจใหม่ทุกครั้ง |

สำเนามีสถานะบนทุกหน้า หากยกเลิกหรือเป็นฉบับเก่า จะมีข้อความขนาดใหญ่สีจางประกอบ ยอดเงิน ชื่อ รายการ และเลขเอกสารยังมาจากต้นฉบับ ไม่เปลี่ยนเป็นราคาปัจจุบัน ระบบไม่ออกเลขใหม่หรือเขียนทับต้นฉบับ

ใช้ปุ่มพิมพ์ในหน้าเว็บเพื่อให้ระบบตรวจสถานะอีกครั้งก่อนเปิดหน้าพิมพ์ ถ้าตรวจไม่ได้ เช่น การเชื่อมต่อขาด จะไม่เปิดพิมพ์จากคำสั่งนั้น ให้เชื่อมต่อแล้วลองใหม่ ปุ่ม **Refresh PDF status** ตรวจทั้งสถานะไฟล์และสถานะเอกสารใหม่ด้วย

### อ่านสถานะอย่างไร

| ข้อความ | ความหมาย |
|---|---|
| CURRENT / Current revision | ยังเป็นเอกสารฉบับปัจจุบัน ณ เวลาที่ตรวจ |
| CANCELLED | ออเดอร์หรือคำสั่งผลิตถูกยกเลิกแล้ว ต้องดูประวัติประกอบ |
| VOIDED | รายการรับเงินนั้นถูกยกเลิกจากการบันทึกผิด ไม่ใช่ใบรับเงินที่ยังใช้ได้ |
| SUPERSEDED | มีเอกสารฉบับใหม่กว่า ใบนี้เก็บไว้ดูประวัติ |
| UNDER REVIEW | ใบผลิตกำลังแก้ไข ยังไม่ควรใช้เป็นคำสั่งผลิตปัจจุบัน |
| Older order revision | ใบผลิตอ้างอิงออเดอร์ฉบับเก่า |
| ARCHIVED | เก็บออกจากรายการทำงานประจำแล้ว ยังเป็นประวัติที่ค้นได้ |
| EXPIRED | ใบเสนอราคาพ้นวันสิ้นสุดที่ระบุ |
| Payment details changed | QR รับเงินที่เก็บในใบต่างจากค่าปัจจุบัน ให้ตรวจข้อมูลรับเงินกับร้านก่อนจ่าย |

การยกเลิกออเดอร์ไม่ได้ทำให้ใบรับเงินจริงกลายเป็น VOIDED โดยอัตโนมัติ ใบรับเงินยังเป็นหลักฐานเหตุการณ์เดิม ส่วนรายการคืนเงินหรือแก้เงินต้องดูแยกตามขั้นตอนเดิม การเก็บออเดอร์เข้า Archive ก็ไม่ได้แปลว่าเอกสารถูกยกเลิก

สถานะในสำเนาเป็นข้อมูล **ณ เวลาที่พิมพ์ไว้บนใบ** หากนำไฟล์เก่าไปใช้อีกภายหลัง ควรดาวน์โหลดสำเนาที่ตรวจใหม่หรือใช้ปุ่มพิมพ์ในระบบ ต้นฉบับและสำเนาที่ส่งออกไปแล้วไม่เปลี่ยนเองตามข้อมูลในร้าน

## เปิดการเก็บอัตโนมัติอย่างไร

ส่วนนี้เริ่มต้น **ปิดไว้** เจ้าของ `ADMIN_PROMAX` เป็นผู้เลือกเปิดหรือปิดเอง พนักงาน ADMIN และแผนกอื่นแก้ค่านี้ไม่ได้

1. เข้าบัญชีเจ้าของ เปิด **Payments & delivery / รับเงินและส่งสินค้า**
2. เปิดส่วน **Automatic archive → Owner archive settings**
3. อ่านเงื่อนไข แล้วเลือก **Enable automatic archive**
4. ใส่เหตุผลและกด **Save archive settings**
5. ถ้าการเชื่อมต่อขาดหลังบันทึก ให้กด **Retry archive settings** เพื่อตรวจคำขอเดิม

เปิดค่านี้ไม่ได้ย้ายออเดอร์เก่าทั้งหมดทันที ระบบเริ่มนับ 15 วันเมื่อสังเกตพบว่าแต่ละออเดอร์พร้อมตามเงื่อนไขครบ ไม่เดาว่าข้อมูลเก่าเคยพร้อมมาตั้งแต่วันไหน การปิดแล้วเปิดใหม่หรือบันทึกการตั้งค่าใหม่จะเริ่มรอบรอใหม่

### ออเดอร์แบบไหนจึงถูกเก็บ

- งานปกติ: ส่งครบ รับเงินครบ ไม่มีเงินรับเกิน ไม่มีปัญหาผลิต คำขอลูกค้า รายการเตรียมส่ง ใบผลิตที่ยังไม่เสร็จ หรือร่างออเดอร์ที่เปลี่ยนแต่ยังไม่ยืนยันค้างอยู่
- งานยกเลิก: เจ้าของตกลงยอดสุดท้ายแล้ว จัดการเงินจริงจนตรงข้อตกลง และเคลียร์งานค้างครบ ไม่บังคับให้จ่ายราคาเต็มของออเดอร์เดิมที่ยกเลิก
- เงื่อนไขต้องคงพร้อมตลอดช่วงที่ระบบตรวจเป็นเวลาอย่างน้อย 15 วัน และผ่านการตรวจล่าสุดก่อนเก็บ

เมื่อข้อมูลสำคัญเปลี่ยน ระบบตรวจพบและเริ่มนับใหม่ หากมีงานค้างจะหยุดนับก่อน เช่น รับ/คืน/แก้เงิน เปลี่ยนออเดอร์ งานผลิต ปัญหาหรือคำขอลูกค้า รวมถึงกิจกรรมที่เกิดแล้วปิดจบไประหว่างรอบตรวจ

ระบบทำเป็นรอบและครั้งละจำนวนจำกัด โปรแกรมกับงานเบื้องหลังต้องเปิดอยู่จึงจะตรวจได้ ถ้าปิดเครื่องจะมาตรวจต่อเมื่อเปิดใหม่ ไม่รับรองว่าจะย้ายข้อมูลตรงวินาทีที่ครบ 15 วัน หน้าเจ้าของมี **Last scan** และ **Waiting** ให้ดู กด **Reload archive settings** เพื่ออ่านค่าล่าสุด

### เมื่อเก็บแล้ว

- ใช้ **Include archived orders** ในหน้ารับเงิน/ส่งสินค้า หรือค้นหาประวัติตามสิทธิ์เดิม
- เจ้าของเปิดกลับมาในรายการทำงานได้ การเปิดกลับไม่ได้ย้อนการยกเลิกออเดอร์ และระบบเก็บอัตโนมัติจะเริ่มรอใหม่
- หากมีงานใหม่ที่ระบบอนุญาต เช่น รายการเงินหรือคำถามลูกค้า ระบบแสดงกลับมาตามกฎเดิม และตรวจเงื่อนไขใหม่ก่อนเก็บอีกครั้ง
- เก็บผู้ทำเป็นระบบ พร้อมเหตุผล เวลา และข้อมูลนโยบายที่ใช้ แยกจากการเก็บที่เจ้าของกดเองได้ในรายละเอียดประวัติ
- เอกสาร ยอดเงินจริง การส่งที่เกิดจริง และยอดขายย้อนหลังของออเดอร์ปกติยังอยู่ตามกฎเดิม

การเก็บที่เจ้าของกดเองยังใช้หน้าตรวจผลและเงื่อนไขเดิม ส่วนนี้ไม่ลบออเดอร์ ไม่ลบไฟล์ ไม่ล้างร่างเก่า และไม่เพิ่มปุ่มย้อนการยกเลิกออเดอร์ งานเหล่านั้นยังเป็นรายการค้างแยกกัน

## การสำรองและทดลองกู้คืน

ค่าตั้งและข้อมูลช่วงรอรวมอยู่ในสำรองข้อมูลด้วย สำเนาที่เปิดในโหมดทดลองกู้คืนไม่รันงานเก็บอัตโนมัติ หากจะเปลี่ยนสำเนานั้นเป็นระบบใช้งานจริง ผู้ติดตั้งกับเจ้าของต้องตรวจค่าตั้งก่อนเปิดงานเบื้องหลังตามขั้นติดตั้งเดิม
