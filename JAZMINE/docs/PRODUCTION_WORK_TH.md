# รับงานและบันทึกเริ่ม–จบงานแต่ละแผนก

**เพิ่มในรอบถัดมาแล้ว:** รายงานปัญหา ของเสีย งานทดแทน และยอดพร้อมส่ง ดู `PRODUCTION_ISSUES_AND_READINESS_TH.md` ข้อความ “ยังไม่เปิดพร้อมส่ง” ด้านล่างเป็นบันทึกของรอบเริ่ม–จบงานเดิม

## วิธีเปิดใช้งาน

หยุดโปรแกรมเดิมด้วย Ctrl+C แล้วเปิด `START_JAZMINE.cmd` ใหม่ ใช้บัญชีและข้อมูลเดิม จากนั้นเลือกเมนู **ວຽກຜະລິດ / Work queue**

ใบผลิตที่ออกฉบับพร้อมแล้วจะเข้าคิว ยังไม่ถือว่าเคยเริ่มผลิตจนกว่าพนักงานจะกด Start เอง หน้าจอส่วนใหม่นี้ใช้ภาษาลาวผสมภาษาอังกฤษตามกติกากลาง

## ใครทำอะไรได้

| ผู้ใช้ | สิ่งที่ทำได้ในคิวนี้ |
|---|---|
| เจ้าของ ADMIN_PROMAX | ดูทุกแผนก และกดเริ่ม–จบงานแทนแผนกได้ |
| พนักงาน ADMIN | ดูภาพรวม สถานะ และประวัติทุกแผนกได้ |
| PRINTING, HEAT_TRANSFER, LASER, SIZE_SORTING, SEWING, QC_PACKING | ดูและกดเริ่ม–จบเฉพาะงานของแผนกตนเอง เห็นสถานะของขั้นก่อนหน้าเท่าที่จำเป็นต่อการรับงานต่อ |
| GRAPHIC | ใช้หน้าเตรียมใบผลิตและไฟล์กราฟิกตามเดิม งานกราฟิกเป็นส่วนเตรียมงานก่อนการผลิตทั้งหกขั้น |

คิวนี้แสดงแบบ ผ้า ไซซ์ จำนวนจัดผลิต และไฟล์ตามฉบับใบผลิต ไม่มีช่องราคาขาย ยอดเงิน หรือเบอร์โทรลูกค้าให้ฝ่ายผลิต

## รับงานและทำงานต่อ

1. เลือกงานแล้วกด **ເປີດວຽກ / Open** ตรวจเลข PS ฉบับ กำหนดส่ง จำนวน แบบ และไฟล์
2. กด **ເລີ່ມ / Start** เมื่อรับและเริ่มงาน ถ้ามีเรื่องต้องบันทึกเพิ่มเติมให้กรอก Note ได้
3. กด **ສຳເລັດ / Complete** เมื่อทำงานในแผนกของตนเสร็จ ระบบเก็บผู้ทำและเวลาให้อัตโนมัติ
4. ใช้ช่อง Status เพื่อกลับมาดูงานที่เสร็จแล้ว หรือเลือก All

ลำดับคือ **พิมพ์ → รีด → เลเซอร์ → แยกไซซ์ → เย็บ → QC/แพ็ก** คำว่า QC ในเอกสารเดิมตรงกับแผนกบัญชี `QC_PACKING`

แผนกถัดไป Start ได้เมื่อขั้นก่อนหน้า Start แล้วหรือ Complete แล้ว จึงทำงานซ้อนกันได้ แต่ Complete ได้เมื่อขั้นก่อนหน้า Complete แล้วเท่านั้น การเริ่ม QC ไม่ทำให้เย็บถูกปิดให้อัตโนมัติ และข้ามขั้นที่ยังไม่เริ่มไม่ได้

ไม่มีช่องให้กรอกจำนวนรับ/ทำเสร็จซ้ำทุกแผนก จำนวนในหน้าจอคือจำนวนที่จัดไว้ในใบผลิต ไม่ใช่จำนวนผลิตเสร็จแยกชิ้น หากต้องแยกชุดให้พร้อมคนละเวลา ให้แยกเป็นหลายใบผลิต

## ค้นหาและติดตาม

คิวเรียงงานด่วนก่อน ตามด้วยกำหนดส่งใกล้สุด และใบที่ออกก่อน ค้นด้วยเลข PS เลขออเดอร์ หรือชื่อลูกค้าได้ เจ้าของกับแอดมินเลือกดูทีละแผนกได้ หน้าจอแสดงครั้งละ 50 ใบแรกและแจ้งเมื่อยังมีงานอื่นให้ค้นเพิ่ม

หน้าจอโหลดสถานะใหม่ทุก 30 วินาทีเมื่อเปิดดูอยู่ หรือกด Reload เองได้ ระหว่างกำลังบันทึกหรือรอลองคำขอเดิมจะไม่เปลี่ยนงานให้

หากการเชื่อมต่อขาดหลังบันทึก ให้ใช้ **Retry** ระบบส่งคำขอเดิมและไม่สร้างการเริ่ม/จบหรือประวัติซ้ำ

## เมื่อแก้ใบผลิตหรือออเดอร์

- เปิด PS เป็นร่างแก้ไขแล้ว งานฉบับเดิมยังอ่านประวัติได้ แต่ไม่รับ Start/Complete เพิ่มจากคำสั่งที่กำลังแก้
- เมื่อออก PS ฉบับใหม่ สถานะงานของฉบับใหม่แยกจากฉบับเก่า งานเก่าไม่ถูกลบ และไม่ถูกนำไปนับว่าเสร็จให้ฉบับใหม่โดยอัตโนมัติ
- คิวและรายละเอียดจะแจ้งว่ามีงานในฉบับอื่น ให้ตรวจผลกระทบกับแผนกที่เกี่ยวข้องก่อนเริ่มงานฉบับใหม่ เลือก PS version เพื่อดูประวัติและไฟล์เดิมได้
- เมื่อออเดอร์มีฉบับใหม่ ต้องตรวจใบผลิตเก่าและจัดชุดจากออเดอร์ฉบับใหม่ก่อนใช้ Start/Complete ต่อ ไม่เปลี่ยนจำนวนหรือไฟล์เก่าให้เอง
- ยกเลิกใบผลิตแล้ว งานจะออกจากคิว แต่ประวัติยังอยู่ เจ้าของ/แอดมินเปิดจากลิงก์ Work ของฉบับใบผลิตในหน้าเตรียมใบผลิตได้

ขั้นนี้ยังไม่มีการโอนงานที่ทำไปแล้วระหว่างฉบับหรือการตัดสินว่างานเดิมใช้ต่อได้เท่าไร เรื่องนี้ต้องเชื่อมกับปัญหา ของเสีย และงานทดแทนในช่วงถัดไป

## สิ่งที่ยังทำต่อ

ต่อไปคือรายงานปัญหาแบบทำต่อหรือหยุด ให้เจ้าของ/แอดมินจัดการปัญหา บันทึกของเสีย สร้างงานทดแทน และคำนวณจำนวนที่พร้อมส่ง

ตอนนี้สถานะ QC Complete เป็นบันทึกจบขั้น QC ของใบผลิตฉบับนั้น ยังไม่เปิดยอดพร้อมส่ง การรับเงิน หรือการยืนยันส่งสินค้า

## ผลตรวจรอบนี้

ชุดทดสอบระบบรวม 39 กรณีผ่าน และตรวจส่วนคิวงานฉบับล่าสุดซ้ำหลังปรับหมายเหตุให้เว้นว่างได้ ทดสอบครบทั้งหกแผนก การเริ่มซ้อนกัน การห้ามจบก่อนขั้นก่อนหน้า การกดพร้อมกัน/ส่งซ้ำ สิทธิ์ที่เปลี่ยนแล้วมีผลทันที ไฟล์เฉพาะฉบับ ประวัติเก่าหลังแก้ PS และการปฏิเสธคำสั่งจากออเดอร์เก่า

ทดสอบผ่านเบราว์เซอร์จริง เจ้าของ Start/Complete พิมพ์และรีดตามลำดับ เริ่มเลเซอร์โดยไม่กรอกหมายเหตุ ส่งคำขอเดิมหลังการเชื่อมต่อขาดโดยได้ประวัติครั้งเดียว พนักงานพิมพ์เห็นเฉพาะงานของตน ไม่มีปุ่มทำแทนแผนกอื่น ไม่มีราคาขาย และหน้าจอ 320/390 พิกเซลไม่ล้น ตรวจคุณภาพโค้ดและการสร้างโปรแกรมผ่าน

ใช้ฐานทดสอบในหน่วยความจำแยกจากข้อมูลจริง ไม่แก้ออเดอร์หรือเริ่มงานแทนเจ้าของ ภาพตัวอย่างอยู่ใน `test-results/production-work-owner.png` และ `test-results/staff-mobile.png` ยังไม่ได้ตรวจการทำงานพร้อมกันหลายเครื่องบนฐานข้อมูลภายนอกหรือการผลิตจริงหน้าร้าน
